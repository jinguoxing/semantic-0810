# PR-1 通过后才使用：PR-2 / PR-3 续接

三个 PR 按既有实施说明第 10 节顺序推进。不要在同一工作目录并行写入 Workspace/Task/Surface；
下一 PR 的基线必须明确包含上一 PR 已批准的变更。上一 PR 尚未合并时，先确认是否采用有明确依赖的堆叠分支，不自行 rebase/merge。

```text
基于 PR-1 已批准成果核对真实 HEAD，不重复重写结果组件。
目标：指标/资源详情不是 Toast 假跳转，而是真正传入对象、定义引用和已知条件；保留原任务内方案承接；正式指标查询按自身真实依赖、维度、时间与授权处理；有实质歧义才复用 ClarificationBlock，提交后继续原请求；定义阅读不查数。

```


## 授权实施/提交时

用明确语句指定当前 PR、批准计划和起点，不只说“继续”。开发完成且评审通过后才另行授权提交或推送。
记录实际 SHA；未运行的测试、未具备的服务及只演示的路径不得改称“全链路完成”。
