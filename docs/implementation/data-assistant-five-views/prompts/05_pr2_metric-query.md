## 03｜工作项一：接通入口，但不要把“进入”当“执行”

### 3.1 入口必须传递的含义

沿现有参数兼容传递：入口来源、明确的对象引用、已知条件、原始请求。必要时可增加轻量 `entryContext`；这是提案名称，优先复用现有字段。

| 情形 | 处理 |
| --- | --- |
| 从指标详情进入 | 携带指标身份与实际可得的定义引用；不以展示名重新搜索后任取第一个。 |
| 从资源详情进入 | 携带真实资源身份；没有资源到指标的可靠映射就不能冒充指标入口。 |
| 在当前数据方案内继续问数 | 保留当前 Task、已选输入与条件，不因为能力切换另起空任务。 |
| 用户从统一入口提出指标问题 | 用现有解析/服务定位实际可见指标；有歧义才进入本轮澄清。 |

进入按钮只表明已知对象或用户动作意图，不能补造用户没有提出的查询。没有时间或问题时，只补必要内容；条件与查询意图已明确时，按既定执行策略继续。

### 3.2 导航、去重与恢复

旧记录中的 App 同时使用 `currentNav` 和 `viewTab`。实施时核对实际条件分支，避免只改其中一个导致仍停在原详情；不要借此重写全局路由。

同一次进入不得因重渲染、重挂载或重复点击而创建多个 Task 或重复发出业务查询。沿用既有入口消费标识/幂等语义；确实缺少时再最小补充，不新增持久化中心。

任务恢复不是重新消费入口，不重新运行原查询。切换任务后旧响应不能写入新任务或打开其右侧。未提交业务修改影响安全施工时先确认，不能自行丢弃。

### 3.3 对象身份和版本

不得默认 `met_*`、`res-*`、`r01/r04/r05` 属于同一 ID 空间。真实关联来自明确映射；演示映射单独隔离，不把同名当同一对象。

传入的定义版本是引用，不是查询授权。新的查询按权威服务既有规则核定适用定义，响应记录实际采用的版本；存在实质定义冲突时依原规则澄清/拒绝，不静默换指标。未提供版本就如实说明，不能编一个版本号贴图。

## 04｜工作项二：正式指标查询按真实依赖执行

### 4.1 三类处理，仍在同一任务体系

| 请求语义 | 应做的事 | 不应做的事 |
| --- | --- | --- |
| 问指标定义 | 授权读取正确定义，直接解释，详情按需展开。 | 为定义问答要求先填数值查询全部条件或调用数据运行。 |
| 查明确指标值 | 补足必要条件、核验适用定义与依赖、按原策略查询，消费真实结果。 | 重复找同一个指标；为查人口强行加入床位。 |
| 指标口径不唯一 | 保留问题与已知条件，生成真实可见选项，显式提交后继续。 | 按置信度、权限多少或数组首项静默代选。 |

这不是新建三种用户模式或强制导航。可在现有请求/计划合同增加最小判别信息；兼容原没有新字段的计划，仍按原组合分析语义处理，不能默认全部获得指标直查能力。

### 4.2 校验边界

正式指标查询检查该指标实际执行依赖、版本、支持的维度、时间覆盖、人群口径和授权。正式指标可能自身也是多源或复合指标，不能因为对用户只显示一个指标就跳过内部依赖。

原人口与床位组合计算继续使用原角色、关联、时间、粒度及执行门禁。禁止空 Core、伪造 READY、伪造搜索事件或全局 `return true` 绕过检查。

`expectedSearchRevision` 等字段应按现有/确认后的兼容合同真实传递：没发生搜索，不创建一次假搜索来凑版本；也不随意改写字段含义让前后端失去一致性。合同无法支持直查时列为该路径的最小依赖。

### 4.3 已知条件不重复询问

只缺时间就只问时间；缺地区与时间时可一次提出两项必要缺项，不必强行拆成两轮。正式定义已经明确的人群，不再要求用户重新决定。

请求时间、实际数据时间与运行时间分别表达。不能用最新覆盖月份替换用户请求月份。月末存量不默认跨月相加，比率不默认取各组比率平均。

已明确“查询”的请求，在原策略允许时直接推进；原策略需要的校验与确认继续保留。用户要求“先看方案”时只预览，不提前执行。不引入一张所有指标查询都必须经过的完整计划页。

### 4.4 服务端仍是执行依据

前端只传经合同允许的对象引用与请求条件；不能把可修改的 UI 公式、SQL 或查询权限当作执行事实发送。服务端需校验对象归属、版本、参数、实际权限与必要依赖。

已有服务能满足就适配；没有确认的接口或结果字段，先在计划中写明最小缺口。可以验证隔离演示，不能写一个看似生产的 URL 再用本地常量返回成功。

## 05｜工作项三：口径选择沿用原决策生命周期

本轮使用 `ClarificationBlock`，业务选项来自实际可见定义。设计样例是“在营可用养老床位数”与“养老床位核定数”，不是修改正式指标定义。

| 时刻 | 组件行为 | 业务含义 |
| --- | --- | --- |
| 初始 | 两项均未选择，“使用此口径继续查询”不可提交。 | 尚未决定本次采用哪一口径。 |
| 点击选项 | 仅本地选中、允许提交。 | 选择草稿，不执行查询。 |
| 提交中 | 防重复、保留选择，显示实际提交状态。 | 不提前显示“已确认”。 |
| 确认成功 | 按原 Task 决策状态收拢为对应摘要。 | 仅表示口径已采用，不表示查数成功。 |
| 后续查询中/成功 | 沿原运行链分别显示查询状态/结果。 | 使用本次所选定义和已知条件。 |
| 确认失败 | 保留选择与错误，允许原动作重试。 | 不伪造确认或结果。 |
| 确认已成功、查询失败 | 保留已确认口径，反馈查询失败。 | 不能将已确认选择重置成未选择，也不能再次提交整项决定冒充重试。 |
| 请求改变、原决定失效 | 显示只读失效说明，无旧提交入口。 | 不让旧选择修改新问题。 |

提交超时且接受状态未知时，遵循既有运行/幂等规则确认状态或安全重试；不能猜测“肯定没执行”。

定义可见不等于数值可查。用户选择的口径不可查询时，说明实际限制；允许查看已授权定义，但不自动改成另一项有权口径。

右侧默认关闭。此处不展开数据源、字段清单、完整指标管理页或权限矩阵。按钮文案可按既有决策数据兼容配置，不为这两项选择复制一个新的澄清组件。

## 06｜工作项四：指标答案与本次定义

### 6.1 图 01 的轻量答案

复用 PR-1 标量结果展示，正文直接回答；名称、数值、单位、实际统计期间、地域、人群与必要限制就近显示。没有比较请求时，不补环比、排名、趋势或大 KPI 卡。

“20,000 人”只属于五图人工设计数据，不是通用查询默认值。真实模式显示服务返回的数值；没有返回不能填 20,000，也不能显示 0 冒充缺失。

不要解析格式化字符串回推数值，不建与 PR-1 独立的指标结果 Store。需要最小字段兼容时复用原结果合同，说明旧任务恢复和旧结果显示方式。

### 6.2 查看本次定义

“查看指标口径”绑定该次答案实际使用的定义，而不是点击时按标题重新搜索“最新指标”。同一右侧宿主展示：名称、含义、单位、必要范围、时间语义、实际引用版本及来源中确有的内容。

只读打开不发起业务查数，不改变需求版本。返回时保持当前答案；不把定义编辑、发布、变更、审批等管理操作复制进来。

本轮只完成本次指标答案的定义查看。任意历史结果独立授权读取、历史依据恢复与结果定向解读仍属于 PR-3。当前引用内容未提供时如实说明，不用最新对象补作历史证据。

### 6.3 基本异常

无记录、NULL、真实 0、被抑制值、不可计算必须按结果合同区分；未知状态不猜。服务失败/超时不输出成功卡；没有真实覆盖不得换成最近月份。任务或定义发生变化后旧响应不能覆盖新请求。
