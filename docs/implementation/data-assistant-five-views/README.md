## 3. Cursor 操作顺序

**第一次，Plan：**新建一个“Semovix PR-1 结果视图”的会话。手动 `@semovix-data-assistant` 选中规则，引用本 README、inputs/01、inputs/02。
把图 03/04 作为图片附件加入，复制 `prompts/01_plan_pr1.md` 的指令块。要求生成一份简短 `PR1_PLAN.md`，先不写业务代码。
Cursor 的 Plan Mode 支持先研究代码、生成可评审计划，再构建；计划保存到工作区后，后续会话才容易明确引用。

**第二次，Agent：**你确认计划没有重复五套页面、放宽权限、造数或扩大范围后，引用批准的计划，复制 `prompts/02_implement_pr1.md`。
让它真实改代码、运行测试、导出图 03/04 的实现截图，输出 `PR1_REPORT.md`。不要用“继续优化”替代明确批准的范围。

**第三次，只读 Review：**用 `prompts/03_review_pr1.md` 审查本 PR 实际差异和证据。评审可以另开会话，但不要让第二个 Agent 同时写同一批文件。
代码 diff 以记录的 `PR1_START_SHA` 为起点，包含本 PR 未提交和新文件；不要默认将与 main 的所有差异都当本轮修改。
只修真实合同违约或本 PR 引入的回归，不为了视觉评分追加能力。

**通过后再 PR-2 / PR-3：**按 `prompts/04_continue_pr2_pr3.md` 逐项启动。下一个 PR 的基线需包含前一个已批准成果。
这里的“PR”是增量工作包称呼，不等于现在自动向远端创建 Pull Request。

## 4. 本轮只做什么

| PR | 目标 | 首要图片 | 开始条件 |
| --- | --- | --- | --- |
| PR-1 | 数值/结果引用兼容 + compact/full + 同结果图表/数据 + 计划/结果主体与操作整理 | 03/04 | 本轮计划经确认 |
| PR-2 | 明确指标/资源入口与口径澄清、实际指标查询分支和定义读取 | 01/02 | PR-1 成果明确并批准进入 |
| PR-3 | 指定历史结果读取、原依据和明确对象解读 | 05 | 前置结果合同可用并批准进入 |

第一阶段 A 的智能滚动/决策/建议仍独立。仅回归已存在的行为，不能让 PR-1 顺手补完 A 或重写找数。
PR-1 可以为标量补展示结构，但这不等于已经接通图 01 的正式指标查询；可以保留历史身份，但不等于实现图 05 全部服务。

## 5. 特别重要的设计纠偏

- 图 03：“类型”只显示“本次计算”，不得把“不标成新增正式指标”等设计指令写进 UI；分母明确是同期 60 岁及以上常住人口数。
- 图 04：聊天不默认重复完整四列表，右侧当前 Tab 展示当前视图；内嵌结果允许存在，后来展开不改写历史。
- 图 05：删除多出的其他街镇、全区范围、固定来源、更新日期及“待确认/查询完成”；仅阅读解读对应历史结果。
- 原业务 Mock 与设计样例是两组独立数据。不得为贴图覆盖原 Fixture，也不从带单位字符串/比率倒推缺失原值。
- 图片蓝按钮不是权限判定；输入完整不代表授权；定义可见不代表数值可查询。

## 6. 计划和交付最小内容

`PR1_PLAN.md`：实际分支/SHA/工作区状态、复用位置、拟改文件、兼容方式、依赖与测试、停止条件。
`PR1_REPORT.md`：起点 SHA、实际改动、完成路径/演示路径/待依赖分列、实际测试命令与结果、未运行原因、03/04 实现截图路径。
这些是待 Cursor 执行时创建的记录。本包不预填假通过、假截图或假提交。

验收不是“所有测试都应当通过”一句话：实际检查同结果同口径、切换不重算、无数据不填零、旧计划拒绝、迟到结果不抢面板、HTTP 不回退 Mock。
已存在失败必须有同环境基线证据；环境缺失如实记录，不扩大本 PR 去重建 CI 或后端。

## 7. 规则的使用方式与局限

规则文件采用 `.mdc` 与 `alwaysApply: false`，没有 `description` / `globs`，属于手动调用型。每个开发/评审会话主动 @ 该规则，并确认它已在上下文中。
它没有全局强制修改其他模块，不保证模型永不走偏；仍需要计划确认、差异检查和测试。
普通规范留在 Markdown 文件中，不把几份长方案全塞进规则，也不引入新的 Skill 或 Spec Kit 流程作为本次前提。
