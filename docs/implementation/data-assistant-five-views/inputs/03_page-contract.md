## 00｜本合同的地位与范围

本合同不替换 V1.3 主方案，不重新打开已冻结的 Find Data V1，也不增加第一阶段 A-01、A-02、A-03 的工作量。A 批次继续按原任务单推进；本文用于后续问数与指标查询的设计评审。

**承接既有规则：**找数、问数、分析按需进入；历史引用不被最新对象替代；查看不等于选择；覆盖、就绪、完成分开；执行前仍遵守已有权限、版本、关系与口径校验。来源为 V1.3 第 1.1、1.6、2.2—2.8、6.2—6.6 节。fileciteturn444file0L12-L38 fileciteturn432file0L11-L30

**本轮设计细化：**区分“问定义、查指标值、基于数据计算、解释结果”四种请求；确定五张状态图的内容与动作；提供统一演示数据、异常状态和动作/数据语义对照。它们是拟采用设计，不是对现有实现的描述。

本轮不重新核验仓库 HEAD、不修改代码、不生成五张设计图片。现有代码是否支持本合同中的动作和数据，进入实现时逐项核对；不能用旧的审查结论代替新的工程验收。

## 01｜功能身份：问指标属于问数体验，不另建一套助手

### 1.1 用户请求的四种处理

| 请求 | 示例 | 处理与输出 | 不应发生 |
| --- | --- | --- | --- |
| 了解指标定义 | “在营可用床位和核定床位有什么区别？” | 读取有权查看的定义，解释含义、适用范围及差异。 | 为回答定义执行业务数据查询；先要求填统计时间和分组字段。 |
| 查询正式指标数值 | “2026 年 8 月浦锦街道的老年人口数是多少？” | 解析实际指标，补足必要条件，按正式定义及其支持的维度查询。 | 重新编辑正式指标；让用户重新挑全部底层表。 |
| 基于资源计算答案 | “用已选人口与床位数据，比较两个街镇每千名老人床位数。” | 承接已选资源、范围和口径，准备有效计算并返回结果。 | 把临时计算标成企业正式指标；在找数阶段提前宣称已算出结果。 |
| 解释已有结果 | “在营可用床位那份结果为什么有差异？” | 先定位结果，描述有依据的差异；进一步分析取决于实际数据与方法。 | 用最新结果替代所指结果；仅凭比率给出确定原因或建设规模。 |

这四种是处理语义，不是四个菜单、四种聊天模式，也不要求增加四个状态枚举。Ask Data 可以消费指标、数据资产或已有查询服务，不等于直接查询原始表。

正式指标定义仍归指标治理；找数没有发现正式指标时，不能自行发明公式并标记为正式指标。允许后续形成“本次计算”，但必须明确其任务范围和非正式性质。fileciteturn443file19L788-L824

### 1.2 本轮设计包含与排除

**包含：**指标定义阅读、正式指标查询、必要口径澄清、已有数据方案承接、有效计算准备、结果摘要、图表/数据视图、按需依据、指定结果追问、基本异常。

**排除：**新建指标治理、任意公式编辑器、通用 SQL 编辑器、跨源任意 Join、预测/因果/优化引擎、独立看板、报告与分享、文件上传、周期任务、新任务中心或新的权限体系。图表和历史结果是本轮要定义的目标行为，不代表其依赖服务已经具备。

## 02｜入口与上下文合同

### 2.1 四个入口汇入同一执行页

| 入口 | 应承接的信息 | 进入后的行为 |
| --- | --- | --- |
| Xino 工作台的自然语言输入 | 用户问题及当前已明确的任务上下文。 | 识别是在问定义、查值、计算还是解释；仅澄清实质缺项。 |
| 指标详情的“查询指标” | 指标身份、实际适用定义的引用、已有明确条件及原问题。 | 不再重新发现同一个指标；时间、区域等未明确时仅补这些条件。 |
| 资源详情或找数方案的“用于问数” | 明确选用的资源/方案引用、需求、角色、已知关系与缺口。 | 先判断能否回答目标；需要补充数据时再找数，不默认所有资源都能直接计算。 |
| 某结果的继续追问 | 该结果引用及其口径、时间、范围和允许读取的依据。 | 查看/解释沿用该结果；要求重算时准备新计划，不恢复旧计划执行。 |

“查询指标”“用于问数”等为用户动作语义，映射到现有入口和 typed action；这里不规定新接口路径或必须新建的 actionCode。

业务对象只提供语义上下文，必须经已登记支撑定位到实际可消费资源，不能把业务对象本身当数据表执行。统一发现与分类型消费的边界继续保留。fileciteturn443file18L144-L155 fileciteturn443file18L225-L252

### 2.2 条件处理顺序

先读取用户本轮明确要求，再继承已确定的本次对象与未变化条件。名称或对象有冲突时澄清，不用“优先级”强行消除业务冲突。

只有正式定义或既有合同明确提供、且不与用户要求冲突的默认值，才可使用并简短说明。不得把 Mock 的最近月份、某个默认地区或上一次任务条件静默带入新任务。

定义问答不必填写数值查询的所有条件。数值查询只补对该指标真正必要的时间、人群、区域、维度等信息；已在指标定义中明确的口径，不要求用户重复决定。

“上月”“最近三个月”等相对时间由实际服务按既定日期与时区规则解析，并展示明确起止范围。不得把数据最新覆盖时间当成用户请求时间。请求时间、实际数据时间与执行时间分别表达；覆盖不足时如实说明。

### 2.3 维度、时间和公式边界

用户提出的维度不被指标支持时，说明限制；可以提出有依据的替代路径，但改变口径或问题必须获得明确同意。

时间聚合遵循实际指标定义。月末存量不能默认跨月求和，整体比率不能默认等于分组比率的平均。需要时间序列时按所支持的周期返回，不能只凭两个单月结果画趋势。

选择或切换定义仅改变本次任务引用，不在聊天中修改正式指标。新查询的适用定义由权威服务按既有规则确定；历史结果继续保留其当时实际使用的定义。

## 03｜执行与确认合同

### 3.1 不把每项系统检查变成用户点击

| 情形 | 对用户的处理 | 系统仍需完成 |
| --- | --- | --- |
| 仅询问定义 | 直接解释；不增加“开始计算”。 | 定义读取授权及正确对象定位。 |
| 用户已明确要求查值，条件无歧义 | 在现行策略允许时沿原执行链查询，不强制再走候选和完整计划页。 | 当前执行所需的全部授权、版本、范围及定义校验。 |
| 存在两种会改变答案的口径 | 显示一个主要澄清；显式提交后才采用选择。 | 核验候选定义、所选值和问题仍有效。 |
| 用户要求“先看计算方案”，或现行策略要求确认 | 展示紧凑计算摘要；只保留一次必要确认。 | 原有执行门禁；已确认条件不反复询问。 |
| 权限、资源、关系或时间不足 | 停止本次计算，说明真实原因及现有可行路径。 | 不用前端隐藏或固定提示替代服务端控制。 |

上述为目标交互，不授权修改既有运行合同。当前实现若有明确的确认或权限复核要求，继续执行；是否能合并为后台检查，须在实施时按原策略核对，不由设计稿或编码模型自行取消。

查询请求已经明确表达用户想查数，不代表拥有查询权限。澄清提交按钮“使用此口径继续查询”可以表达继续该次查询的意图，但不能代替受控动作另外要求的确认。

### 3.2 运行期间

对话显示真实的当前状态，例如“正在查询所选指标”，不默认展开完整计划、SQL 或内部工具列表。没有阶段事件就使用单行状态，不画虚构进度百分比。

运行按钮防重复提交。重试遵守现有运行和幂等规则；超时不能直接认定原运行从未执行。取消入口仅在实际运行服务支持时展示，不绘制可点击但无执行语义的按钮。

### 3.3 覆盖、就绪、完成分别表达

原目标含实际服务使用、但本次只执行床位比较时：原目标仍为部分覆盖；用户同意的床位比较在满足条件后可以执行；完成文案只指该次比较。不能通过删掉 Gap 让页面看起来已全部完成。

该规则不要求新增三套状态机。若现有合同无法承接用户同意的部分范围，先说明限制，不能只更换文案就宣称部分执行成功。fileciteturn432file0L11-L30

## 04｜共用执行页与信息布局

### 4.1 母版与页面身份

沿用当前已认可的 Semovix 数据助手执行页，不重画全局导航、Logo、任务历史栏和输入框。设计统一采用 1920 × 1080、16:9 桌面基准；这只是本轮出图规格，不要求生产页面固定像素宽度。

页面身份保持“数据助手”，不同时出现两套“问数工作台 / 问指标工作台”。左侧继续服务任务历史；对话是主推进区；右侧工作区按需展开。

当右侧关闭时，不预留占位空栏，也不摆一张“等待结果”的大卡。右侧打开时，在同一工作区内承接本次计划、结果或依据，不再嵌套第二个右侧栏。

复用现有颜色与字体体系。正文、时间、单位和关键限制保持可读，不靠把字体缩小来塞进整套内容。内部页面编号、设计版本、状态枚举、资源 ID 不出现在真实 UI 文案中。

### 4.2 每个区域只承担一种主要职责

| 区域 | 默认内容 | 不默认展示 |
| --- | --- | --- |
| 对话正文 | 直接回答、必要范围和限制、一个主要推进/查看入口。 | 完整字段表、SQL、权限矩阵、证据长列表。 |
| 当前请求摘要 | 对本次决定必要的时间、范围和口径；自然排版一至两行。 | 同一份上下文在顶部、卡片、输入框上重复三遍。 |
| 右侧结果工作区 | 明确结果身份、实际范围、图表或数据、必要依据入口。 | 模型内部思维链、全部产品能力 Tab。 |
| 依据详情 | 当前结果实际引用的定义、版本和来源内容。 | 固定认证值、“100%可信”或未读取的文档。 |
| 历史决策 | 确认或失效摘要，必要时展开只读内容。 | 可重新提交的旧选择控件。 |

### 4.3 工作区触发规则

普通解释问题先在对话回答；“展开比较”“画图”“列完整明细”已经包含结构化展示意图。内容真实就绪后可以打开相应工作区，不要求用户再点击同义入口。

只要求计算且没有要求完整视图时，完成后给摘要与入口，不抢占页面。等待期间用户关闭、切换任务或转看其他对象，旧请求完成后只提示可查看，不重新打开或覆盖其新选择。

历史结果工作区不随当前最新结果更新；“图表/数据”切换只改变显示，不重新查询、不改变需求版本。上述规则沿用 V1.3。fileciteturn444file1L79-L97 fileciteturn444file2L333-L347

## 05｜统一设计演示数据

### 5.1 目的与标识

以下数值由本合同为设计一致性人工设定，只用于五张状态图及交互原型。**不是生产统计、不是来源文件提供的真实数值，也不替换仓库当前闵行 Mock Fixture。**不要求本轮新增完整演示场景代码。

所有出现数值的设计图，在数据区附近统一显示：**“设计演示数据，非真实业务统计”**。它不是正式产品所有环境中的永久标识；真实环境根据实际数据来源显示。

为避免各图范围和计算互相冲突，只选两个街镇作设计示例，不使用“全区汇总”“全区偏低名单”“正式政策目标”等表述。

### 5.2 口径与范围

| 项目 | 本轮设计样例 |
| --- | --- |
| 地域 | 闵行区：浦锦街道、七宝镇；不同请求可选择其中一个或两个。 |
| 时间 | 2026 年 8 月；本样例假设三项输入均为同期月末统计。 |
| 人口定义 | 60 岁及以上常住人口。该口径仅作为设计样例设定；实际名称与定义以正式来源为准。 |
| 在营床位 | 本样例的“在营可用养老床位数”，区别于核定容量。 |
| 核定床位 | 本样例的“养老床位核定数”，不能解释为即时在营可用量。 |

| 浦锦街道 | 20,000 | 300 | 450 | 15.0 | 22.5 |
| 七宝镇 | 40,000 | 800 | 1,000 | 20.0 | 25.0 |

在营可用比较中，七宝镇比浦锦街道高 **5.0 张/千人**；核定比较中，高 **2.5 张/千人**。只能据此描述所选口径下的差异，不能认定供给不足或计算新增床位规模。

不为图表补造其他月份、街镇、总量、发布日期、认证状态或文件页码。需要这些内容时，先扩充并核对设计数据，不能由生图模型自由生成。

## 06｜五张关键状态图内容合同

**五张是同一执行页的五种状态，不是五个导航页面，也不是固定五轮流程。**每张图有明确的捕获时刻，不能将准备、查询中和已完成混在同一张图里。

### 01｜正式指标直接回答

**页面任务：**证明明确指标查询可以得到直接答案，不重复找数，不为一个数打开整套工作区。

**前置条件：**用户从已明确的指标进入，或系统已唯一解析到指标；2026 年 8 月、浦锦街道、60 岁及以上常住人口口径已明确；既有执行校验已完成，返回成功结果。

**用户输入：**

> 查询 2026 年 8 月浦锦街道的 60 岁及以上常住人口数。

**对话主要答案：**

> 2026 年 8 月，浦锦街道 60 岁及以上常住人口为 **20,000 人**。

就近小字：`2026 年 8 月末统计 · 设计演示数据，非真实业务统计`。

**动作：**一个轻量入口“查看指标口径”。用户点击后在同一右侧工作区查看本次实际引用的定义；不触发查询。额外追问入口必须是已具备的动作，不为排版凑齐三个。

**GUI：**捕获时刻右侧关闭，对话保留自然留白。不放完整计划、字段列表、图表、全套 KPI 卡。

**退出：**可以继续问定义、修改时间或结束。标题和身份保持同一个数据助手。

**配套规则，不另增设计图：**若用户仅问“这个指标是什么意思”，只回答定义，不展示 20,000 人、不产生查数成功状态。截图处于查询完成时刻，不表示执行门禁被省略。

### 02｜指标口径需要澄清

**页面任务：**证明只在会改变答案时澄清，选项使用业务语言，不把用户带入字段配置。

**前置条件：**时间和地区已明确，但“养老床位”可以对应两项实际可发现的不同口径。两项定义的可见性已经符合既有规则。

**用户输入：**

> 查询 2026 年 8 月七宝镇的养老床位数。

**对话主问题：**

> 你要看在营可用床位，还是核定床位？两种口径的数值和含义不同。

| 选项 | 选项说明 |
| --- | --- |
| 在营可用养老床位数 | 用于了解本口径下的在营可用容量。 |
| 养老床位核定数 | 用于了解核定容量，不等于实际可用容量。 |

**主要动作：**“使用此口径继续查询”。未选择时不可提交；不能只点击选项就立即执行；提交成功后才收拢为“已选择：在营可用养老床位数”或对应值。

**GUI：**该时刻右侧默认关闭。两项简短差异留在对话，不打开指标管理或候选数据表选择页。

**退出与异常：**提交中防重复；失败保留选择和错误，允许按原动作重试；成功沿原查询链继续。需求已经改变导致该决定失效时，只读说明，不允许提交。

**禁止：**用候选查询权限高低代替用户的口径选择；未实际查询就在两个选项里预填 800/1,000；为了显示推荐而自动默认其中一项。

### 03｜从已有数据方案进入问数，查看本次计算

**页面任务：**证明找数成果能结构化承接，且计划准备不等于结果完成。

**前置条件：**已有数据方案明确人口与在营可用床位资源、2026 年 8 月、两个街镇范围；用户本轮明确要求先看计划。原方案如有其他目标缺口，继续保留，不伪造完整覆盖。

**用户输入：**

> 用已选人口和在营可用床位数据，比较 2026 年 8 月浦锦街道、七宝镇每千名老人床位数。先让我确认计算方案，不判断是否充足。

**对话摘要：**

> 已沿用当前选定的人口与在营可用床位资源。此次比较两个街镇的相对水平，不据此判断供给是否充足。

**GUI：**右侧打开“本次计算”，只保留以下主体：

| 内容 | 设计文案/值 |
| --- | --- |
| 计算名称 | 每千名老人在营可用养老床位数 |
| 类型 | 本次计算；不标为新增正式指标 |
| 请求范围 | 2026 年 8 月；浦锦街道、七宝镇 |
| 拟使用输入 | 已选人口指标、在营可用养老床位指标 |
| 公式 | 在营可用养老床位数 ÷ 同期 60 岁及以上常住人口数 × 1,000 |
| 比较方式 | 比较两个街镇，不作充足或达标判断 |
| 边界 | 不代表实际服务需求及使用情况 |

**主要动作：**只在这个计划工作区放“按此方案计算”；对话不再重复同一个主按钮。次要入口为“调整条件”。

现行策略要求的校验入口和确认继续保留；设计不把它们扩展成全屏权限矩阵，也不自行删掉原有门禁。无法取得校验结果时显示待核验，不能画“全部通过”。

**退出：**有效计划经过原校验后执行；执行中显示实际状态；未返回结果前不能出现数值、绿色完成徽章或图表。用户只明确要求计算、没有要求先看计划时，不强迫每次经过本状态图。

### 04｜完整结果：同一结果的图表/数据与按需依据

**页面任务：**证明复杂结果由工作区承载，聊天不重复整张图和整张表。

**前置条件：**对应在营可用床位比较已经成功；用户明确要求查看完整比较图/数据，或工作区当前就在等待这份结果。没有用户后续关闭、切换等阻止呈现的操作。

**用户输入：**

> 展示这次比较的图表和数据。

**对话摘要：**

> 七宝镇为 **20.0 张/千人**，浦锦街道为 **15.0 张/千人**，相差 **5.0 张/千人**。这是所选范围内的相对水平差异，不能据此认定供给不足。

**GUI 标题：**“在营可用床位比较”。

**标题下范围：**`2026 年 8 月末 · 浦锦街道、七宝镇 · 设计演示数据`。

**主体：**同一区域提供“图表 / 数据”切换。图表默认两项横向比较柱；数值为浦锦 15.0、七宝 20.0，轴单位为“张/千人”。数据视图对应同一份结果，列为：街镇、老年人口数（人）、在营可用床位（张）、每千名老人床位数（张/千人）。

切换视图不重新执行、不修改需求。画面捕获一个当前 Tab，不把两套完整视图并排塞进一张截图。

**依据入口：**“查看本次计算依据”。点击后在同一工作区查看实际定义、公式、时间/粒度说明及真实来源引用，并可返回原结果/Tab；不创建第二个右侧栏。不支持的文档或 SQL 入口不展示为可用。

**必要限制：**在当前结果区域就近保留“不据此判断服务供需是否充足”，不只藏在依据详情。

**禁止：**显示全区排名、全区平均、政策目标、其他街镇或其他月份；将两项返回记录说成发现了两项异常；增加未经支持的导出、分享、建看板按钮。

### 05｜指定历史结果继续追问

**页面任务：**证明同一任务可以保留多份结果，追问先绑定正确对象，阅读历史不改变当前计划。

**前置条件：**同一任务已有两份可读取的设计演示结果：

- 在营可用床位比较 · 2026 年 8 月：浦锦 15.0，七宝 20.0。
- 核定床位比较 · 2026 年 8 月：浦锦 22.5，七宝 25.0。

用户明确指向第一份。结果必须有真实可用引用；此为目标设计，不能因当前服务只保存最新结果就用最新值冒充历史。

**用户输入：**

> 回到在营可用床位那份结果，解释浦锦街道为什么比七宝镇低。

**对话开头的轻量绑定说明：**`本次解读：在营可用床位比较 · 2026 年 8 月`。不显示原始 resultId，不增加一张大上下文卡。

**主要回答：**

> 在这份结果中，浦锦街道为 15.0 张/千人，七宝镇为 20.0 张/千人。这能确认所选口径下的相对水平差异；现有结果还不足以判断形成差异的业务原因，也不能推算应新增多少床位。

可以说明进一步需要哪些类型的支撑，但不得预先宣称存在或自动纳入新资源。只有实际提供相应能力时，才给出补充找数动作。

**GUI：**因用户明确要求“回到”第一份结果，打开该份历史结果及其原范围、口径；不把它改成核定床位结果。当前任务计划不因只读打开而切换，历史结果不被覆盖。

**伴随分支，只写交互不另增大图：**

| 后续表达 | 处理 |
| --- | --- |
| A/B 都可能被指代，仅说“这个结果为什么偏低” | 只澄清基于哪份结果，不默认取最新或当前打开面板。 |
| “把在营可用那份改为 2026 年 6—8 月，按月看” | 继承明确的在营口径与两街镇范围，准备新计划并校验时间覆盖；没有多月结果时不画趋势。 |
| 只是切换查看两个结果 | 只读切换，不重新查询、不恢复失效计划。 |
| 旧结果或依据不可读 | 说明不可取得，不回退到核定床位或另一份结果。 |

描述、分解与原因证明继续遵守 V1.3：已有结果可以解释，缺数据或方法时说明不能确认，不能从比率跳到因果和建设建议。fileciteturn444file2L224-L240

## 07｜异常与非成功状态合同

以下是同一执行页的局部状态，不另画八个全新页面，不要求新增同名状态枚举。

| 情况 | 必须表达 | 允许的下一步 | 禁止 |
| --- | --- | --- | --- |
| 指标/对象不唯一 | 实际可见候选的区别及本次缺少的决定。 | 用户选择，必要时查看定义。 | 用最高置信度或最多权限静默代选。 |
| 必要条件不足 | 仅缺失的时间、范围或口径。 | 补足该项后继续。 | 重新问所有已确认信息。 |
| 定义可见但数值不可查 | 明确“可查看定义”和“查询需要权限”的区别。 | 原服务允许时申请或调整；仍可阅读有权定义。 | 补一个样例值、显示 0、把申请成功写成已授权。 |
| 查询无数据 | 当前条件下未返回记录，以及实际范围。 | 查看/调整条件；不自动改条件。 | 将无记录、NULL、被抑制值和数值 0 混为一谈。 |
| 数据覆盖不足或只返回部分 | 所请求范围与实际返回范围的差异及限制。 | 明确同意后按可行范围继续；或补数据。 | 静默改到最近可用月份并宣称原问题已完成。 |
| 失败或超时 | 未得到可确认成功结果，保留问题与已确定条件。 | 按原运行规则查看状态或重试。 | 超时就显示完成；重试绕过授权或重复提交。 |
| 历史结果/引用不可取得 | 明确该对象不可用或无权。 | 返回当前可读内容，用户明确时再发起新计算。 | 最新定义或另一份结果自动顶替。 |
| 分母为零、单位或方法不成立 | 比率不可计算或当前条件不支持，并解释实际原因。 | 修正有问题的条件或补充依据。 | 伪造 0%、无穷大图表或给出肯定式分析结论。 |

正在运行时保留必要上下文，完成后突出真实结果；历史运行失败记录不被新的成功文案改写。用户关闭工作区只改变展示，不等于取消后台任务。

## 08｜动作与数据语义对照

本节写的是页面需要的含义，不是新建 HTTP 接口、数据库表或第二份任务状态。先映射现有对象与服务；现有合同确实缺少时再评审最小补充。

### 8.1 动作合同

| 用户动作 | 所需对象 | 是否改变任务业务条件 | 结果与 UI |
| --- | --- | --- | --- |
| 问/查看指标定义 | 有权读取的指标与适用定义引用。 | 否；可留下当前问题与回答，不修改计算条件。 | 对话解释，详细定义按需查看。 |
| 查询指标值 | 指标引用、明确必要条件、用户请求与执行策略。 | 创建或推进本次查询。 | 真实运行后返回对应结果；失败保留上下文。 |
| 提交口径选择 | 当前有效问题及选择对象。 | 是；影响范围按原变更规则。 | 成功才收拢；失败不假装已确认。 |
| 按当前方案计算 | 有效计划、所需输入与必要校验。 | 发起运行；不擅自重写已确认定义。 | 状态来自真实运行，结果指向该次执行。 |
| 查看结果/本次依据 | 明确结果及其引用。 | 否。 | 打开正确对象；失败不换对象。 |
| 切换图表/数据 | 同一份结果。 | 否。 | 改展示；分页仅读取同一结果。 |
| 解释某份结果 | 明确且有权读取的结果与证据。 | 只解释时不改条件、不重跑原查询。 | 输出支持范围内的解释；额外分析另走原链。 |
| 修改时间、区域、口径 | 明确承接对象与用户变化部分。 | 是。 | 准备新有效计划和结果，保留原历史。 |
| 申请资源查询权限 | 资源、动作和原权限服务要求的背景。 | 不自动选用资源或执行查询。 | 如实显示申请/授权结果，继续原任务。 |

### 8.2 页面最小数据需求

| 数据含义 | 主要用途 | 缺少时的处理 |
| --- | --- | --- |
| 指标身份、名称、定义引用 | 消歧、查定义、保持正式口径。 | 不宣称已唯一定位正式指标。 |
| 单位、可用维度、时间语义与必要条件 | 确定怎么查、怎么解释。 | 只补实际缺项；不猜默认聚合。 |
| 当前有效计划或查询请求引用 | 发起受控执行及事后对应。 | 不用浏览器展示公式替代权威执行计划。 |
| 对应运行结果引用及实际范围 | 结果展示、历史打开和后续追问。 | 不能提供看似完整的历史结果动作。 |
| 指标值或结果行列、单位与空值含义 | 直接答案、图表/数据一致。 | 不从格式化字符串猜出缺失数值。 |
| 来源类型、已返回的限制与执行状态 | 区分演示、实际结果、失败和部分返回。 | 不编造“实时查询成功”或完整覆盖。 |
| 实际引用的定义、版本、摘录或定位 | 本次依据阅读。 | 缺版本/页码就说明未提供，不自动用最新。 |
| 当前允许的动作与权限判断 | 查看、查询、复制等能力。 | 无服务依据不显示已授权或可执行。 |

设计样例中可以用内部演示引用关联对象，但不得把该演示引用注册为正式资源 ID。实际后端未接通的能力在原型中明确为设计演示；生产 UI 不假成功。

### 9.2 实现前必须确认的三组依赖

**指标与查询：**哪项现有服务提供定义、支持维度和实际数值；执行前需要哪些系统校验、哪些明确确认。不能只依据设计图删除当前门禁。

**结果与依据：**如何读取指定结果、实际范围和原引用；历史读取与追问是否可承接。能力未具备时可以先验证设计原型，但不能开放伪历史读取或最新结果替代。

**视觉母版：**后续五张图绑定同一份已认可执行页参考和官方 Logo，不混用历史候选图。图像只能说明展示，不作为新增按钮或数据接口的依据。

上述依赖尚未在本轮重新核验，不将其写成已实现事实；也不在本合同中臆造接口路径或全量后端方案。

### 9.3 冲突与停止规则

业务行为按本合同及 V1.3，布局按评审通过的设计图，实际数据与权限按现有服务合同。三者冲突时先记录并确认，不让编码模型自行补业务流程、数值或授权。

五张状态图、配套动作表和异常表评审通过，即结束本轮设计，不为了视觉评分反复扩展范围。随后只选已批准且依赖具备的一条路径实施并验收，再扩展下一条；不要求一次交付全部 B/C。
