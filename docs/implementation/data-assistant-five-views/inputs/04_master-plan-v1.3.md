## 执行摘要

本方案保留 Semovix 已冻结的“需求—候选—数据方案—权限—分析交接”，吸收三份参考仓库在阅读、决策、答案、依据、方案取舍和成果交付方面的交互组织方式。正文按 Semovix 的功能与用户流程整合，不按仓库拆成多套实现。

本版在 V1.2 的范围取舍、事实/判断/限制分层基础上，收敛五处容易产生不同实现的规则：**找数、问数、分析按需进入；多结果追问先确定对象；目标覆盖、执行就绪与运行完成分别表达；分析结论不超出方法和证据；GUI 根据展示意图承接，不要求用户重复说“打开”。**

这些修正分别并入原有章节，不新增五个功能包，不要求修改已冻结的任务内核。报告、成果保留、分享、临时文件和周期任务仍按原服务条件分别评审。

目标是让用户更容易理解当前任务、完成必要选择、核对依据，并保留需要继续使用的结果；不是把参考仓库的所有页面、卡片和能力累加到执行页。

> **首批范围不变：仅做智能滚动、已确认决策收拢、基于现有可执行动作的下一步建议。**
> 多来源依据、结果视图、任务内成果保留、方案取舍与覆盖说明均为后续内容；不得反向成为首批或 Find Data V1 的新增冻结条件。

## 01｜目标、边界与吸收清单

### 1.1 产品分工与按需进入｜V1.3 修正

| 能力 | 负责的问题 | 本方案的处理 |
| --- | --- | --- |
| Find Data | 为了当前目标，应该使用哪些真实资源？ | 保持现有 Data Solution、候选、缺口及交接合同。 |
| Ask Data | 如何用这些数据计算并回答？ | 后续优化结果、口径、短追问和执行反馈。 |
| Analysis | 结果意味着什么，依据与限制是什么？ | 基于明确结果和可用方法解释；不以自然语言补全缺失证据。 |
| 任务中心 | 如何管理持续任务及周期执行？ | 周期草稿交回现有任务中心，不新建“自动化中心”。 |

上述分工沿用既有产品边界；参考仓库的 Task/Stage 或 MessageResult 不替换 Semovix 领域模型。Find Data 说明资源对目标的支撑，不提前声称 SQL 已执行、预测已完成或报告已生成。

#### 1.1.1 三项能力不是强制三步

| 用户已经具备的条件 | 应进入的处理 | 不应强迫用户做什么 |
| --- | --- | --- |
| 不知道需要哪些资源 | 找数，必要时澄清，再形成数据方案。 | 未明确目标就先选数据源、表和字段。 |
| 资源、指标口径与范围已明确且有效 | 直接准备问数，复用已确定上下文。 | 为进入问数而重复展示候选、重新选择全部资源。 |
| 已有可引用且有权读取的结果 | 基于该结果进入分析；只解释现有结果时无需重跑原查询。 | 重新找数、重新确认未变化的条件。 |
| 分析发现需要额外数据 | 补充找数，按现有评估和选择规则完善输入，再返回当前问题。 | 丢掉原任务，或把新候选自动纳入执行。 |
| 只想找某个资源或查看字段 | 完成资源发现/查看即可。 | 强制形成分析计划、生成图表或报告。 |

直接进入以实际能力和有效输入为前提：资源明确不代表名称已经消歧，指标正式不代表本次可查询。尚缺必要条件时，只补足该项；未知或未支持的入口如实说明，不用默认场景冒充。

> **跳过不必要的交互，不等于跳过权限、口径、关联、版本和执行校验。**

#### 1.1.2 连续工作，而不是功能巡游

```text
同一任务中的当前请求
  ├─ 不清楚用什么数据 → 找数 → 可交接的数据方案
  ├─ 输入和口径已明确 → 问数 → 对应结果与计算依据
  ├─ 已有明确结果     → 分析 → 发现、依据与限制
  └─ 分析需要补充数据 → 返回找数补充 → 继续当前问题
```

此结构说明能力如何承接，不新增四个页面或一套通用路由框架。用户可以在完成找数、得到一个答案或理解一份结果后结束任务；报告、成果保留、分享和周期执行均为可选后续工作。

主链路图与对外说明统一标注：**“找数、问数、分析按需调用，可直接进入、按需返回，不要求依次经过。”**“主链路明确”只描述产品组织；生产是否打通按 11.6 的真实业务验收判断，不由流程图或演示成功证明。

### 1.3 首批明确不做

不重建 Task、Reducer、Scenario Registry、权限服务或 Runtime；不新增 Surface、场景 Fixture、SSE/轮询、上传、报告、分享和调度接口；不引入通用 NLU、建议排序模型、Join Planner 或新菜单。后续批次是独立能力，不连带成为 A 批次的交付义务。

A 批次也不增加多来源阅读器、图表/数据切换、任务成果保留、数据方案覆盖矩阵、替代目标生成、交接新表单或权限申请改造。文档列出这些规则是为后续统一评审，不是批准首批一起开发。

### 1.4 Data Solution 的需求覆盖说明｜沿用 V1.1，后续待排期

**来源实现：**find-ask 的 `DecisionDiscoveryPlan` 展示业务目标、分析对象、维度、数据对象与方案覆盖说明。其预设响应还会同时给出计算和报告内容；前半段的对应说明值得参考，后半段不能被视为真实执行已完成。[S11](#src-s11)[S16](#src-s16)

**拟采用规则：**不新建 `DecisionDiscoveryPlan` 或“决策型数据发现”模块，只将现有 Requirement Hypothesis、资源角色、Coverage、Gap 与可用状态组织成更容易理解的说明。

| 展示层 | 默认内容 | 触发条件 |
| --- | --- | --- |
| 对话 | 简要说明目前能支持什么，以及会影响结论的关键缺口。 | 方案形成、重组完成，或用户询问推荐原因。 |
| 现有 Solution 工作区 | 业务问题、所需数据能力、当前资源支撑和未覆盖项。 | 用户明确查看数据方案；工作区已展示该方案时可原位更新。 |
| 资源/关系详情 | 当前资源口径、角色及关系依据。 | 用户点击对应资源或依据，不默认展开全部字段。 |

以下为展示示例，沿用已讨论的闵行任务；不表示生产资源、文档和计算结果已具备，也不改变冻结场景的资源角色：

| 当前业务问题 | 所需数据能力 | 当前方案支撑 | 边界与缺口 |
| --- | --- | --- | --- |
| 各街镇老年人口规模如何？ | 指定年龄及常住口径的人口统计。 | 当前已选择的人口指标。 | 按本次正式指标定义解释，不扩大为所有老人群体。 |
| 床位相对供给水平如何？ | 与人口维度和时间可对齐的床位统计。 | 当前已选择的在营可用或核定床位指标。 | 两种床位口径不能混用；关联按现有分析门禁验证。 |
| 实际服务使用是否已覆盖？ | 服务使用记录及其业务覆盖范围。 | 已发现的居家养老服务订单候选。 | 仅部分匹配时说明当前未覆盖完整服务使用。 |

数据来源不足时，显示“当前未确认支撑关系”或已登记的缺口；不根据字段名称猜出新的支撑关系，不生成百分比覆盖率，不编造未来床位需求或建设建议。业务覆盖与使用权限分别表达：资源需申请不等于业务不匹配，业务相关也不等于可以查询。

**最小验收（仅该项获批实施时）：**说明中的资源、角色、口径、覆盖与缺口均能回到当前 Data Solution；只读查看不改变方案或触发计算；部分覆盖不能被改写成“完整支撑”。

### 1.6 原目标与可先完成范围｜V1.2 重点完善，后续评审

**来源实现：**discover-0815 场景 B 区分“实际由老年人提出的诉求”和“老年人口规模与整体热线诉求的区域比较”；人级数据受限时，预设对话说明后者不能证明每张工单由老年人提出。这是脚本中的业务区分与取舍表达，不证明系统已经动态识别并执行两套方案。[S17](#src-s17)

**拟采用规则：**先判断替代是否改变问题，再决定要不要修改需求。不可查询、覆盖不足和关系待验证分别说明；不把“先用可用数据”当成无条件继续分析的授权。

| 当前情况 | 必须说明的差异 | 用户动作与状态处理 |
| --- | --- | --- |
| 同口径替代资源 | 对象、口径、时间与粒度是否保持；哪些质量或新鲜度差异仍存在。 | 按既有选择与重评流程替换；不因为名称相近而直接视为等价。 |
| 只能完成原目标的一部分 | 本次能回答哪个子问题，原目标还缺什么。 | 用户明确选择先做该部分后，保留原目标与缺口，在现有计划中限定本次范围；不宣布原目标完成。 |
| 只能回答相近但不同的问题 | 明确列出原问题、可改答的问题以及不能推导的结论。 | 需要明确同意新范围；未经同意只展示建议，不更新当前需求或生成计划。 |
| 没有可靠的可执行替代 | 当前资源、口径或关联缺口。 | 保留缺口及已有补充/申请入口；不创造资源，不用演示结果补全。 |

“改变问题”包括人群、分析粒度或结论对象改变，不只包括换表。资源权限被授予，只解决对应动作的授权问题，不自动解决业务覆盖和关联证据，也不自动把资源纳入本次输入。

#### 最小交互与确认边界

```text
当前目标受限
→ 说明当前限制及一个有依据的可选范围
→ 用户明确接受该范围，或继续完善原目标
→ 接受时通过既有决策与计划合同记录范围；需求或已选输入确有变化时走原失效与重评链
→ 新计划与新结果使用确认后的范围，保留原目标尚未覆盖的内容
```

这是一条条件分支，不是每次找数必走的流程。系统建议可使用一个短说明和两个动作，例如“先做区域比较 / 继续完善原目标”；详情留在现有 Solution。用户已经明确说“那先做区域比较”时，不再强加第二次同义确认。“如果先不用明细还能看什么？”只是咨询，不能被当成接受新目标；指代不清的“继续”沿用现有澄清方式，不猜测同意。

| 时点 | LUI / GUI 与数据行为 |
| --- | --- |
| 建议尚未接受 | 明确标注“可选方案”；保持原需求、已选资源和当前计划状态，不自动切换工作区。 |
| 用户接受 | 通过现有决策/修改动作记录本次范围；需要重评时沿原链推进，必要校验未完成前不写成已就绪或执行成功。 |
| 用户拒绝 | 保留原目标与缺口；可以继续查看依据、按原权限规则申请或调整条件。 |
| 重评失败或仍缺条件 | 显示失败/不足；原结果继续只读保留，不恢复旧计划冒充新范围成功。 |
| 以后返回原目标 | 作为明确的范围变更重新评估，重新检查权限和关联；不直接复用历史权限快照。 |

#### 解释示例，不新增完整业务 Fixture

| 项目 | 用户应看到的含义 |
| --- | --- |
| 原目标 | 识别实际由老年人提出的热线诉求。 |
| 当前限制 | 尚不能确认人级识别链路；所需明细的查询权限未就绪。仅在这些信息当前有权获知时展示。 |
| 可改答问题 | 比较各街镇老年人口规模与整体热线诉求分布。该方案是否可执行仍须真实校验。 |
| 不能推出 | 不能把整体工单称为“老年人本人提出的工单”，不能用整体工单与老年人口的比值冒充老年人的实际诉求率。 |
| 接受后的摘要 | 本次按街镇做区域比较，不识别实际老年诉求人；完整资源与限制可在计划中查看。 |

权限受限不允许系统先读取受限明细再自行聚合绕过限制；只有当前确有权消费、且适合新问题的资源可被使用。无权发现的资源不展示名称、数量或“存在但不可见”的提示。该说明不新增权限维度。

**进入条件与验收：**现有需求修改、方案重评、决策及计划合同能保存明确范围并使旧计划失效；否则只提供说明，不开放一键切换。验收关注“未接受不改状态、接受后不偷换含义、部分工作不写成原目标完成”。不新增通用替代方案服务或跨域演示任务。

#### 目标覆盖、执行就绪与本次完成分别表达｜V1.3 修正

| 判断 | 回答的问题 | 读取依据 | 不能据此推出 |
| --- | --- | --- | --- |
| 原目标覆盖情况 | 用户原本要解决的问题是否都获得支撑？ | 已确认目标、Coverage、Gap 与已知限制。 | 有 Core 就表示完整目标已覆盖。 |
| 本次执行是否就绪 | 用户同意的这次范围是否满足执行条件？ | 当前有效计划、所需输入、权限和关系等原有门禁。 | 原目标部分覆盖就必须阻止所有可行子问题；或用户同意就可跳过校验。 |
| 本次运行是否完成 | 这一份计划实际执行得怎样？ | 对应 Run 与真实结果。 | 本次成功就表示原目标全部完成；或有结果就表示全部步骤成功。 |

例如，原目标包含“人口、床位供给和实际服务使用”，但只具备前两项：

```text
原目标：部分覆盖，实际服务使用仍有缺口。
用户同意的本次范围：人口与床位相对供给比较。
必要输入和执行校验满足后：这次比较可以执行。
运行成功后：这次比较已完成，实际服务使用仍未完成。
```

执行前可说：“可以先完成床位相对供给比较；实际服务使用仍未覆盖，本次结果不回答这部分问题。”执行后可说：“床位相对供给比较已完成；原目标中的实际服务使用仍待补充。”如果本次范围所必需的输入缺失、权限不允许或关联不成立，就不能执行，不能以“部分交付”为理由忽略必要条件。

先做子问题时不删除原目标的未覆盖项；用户明确改为另一个目标时，才按既有需求变更规则更新当前目标，保留历史记录。上述三个判断由现有任务、计划与运行数据派生，不新增状态枚举、三套状态机或三张常驻状态卡。现有合同尚不能承接部分范围时，只给出说明，不用前端文字伪造部分执行能力。

### 1.7 候选用途说明：补充、替代与延伸｜V1.2 展示细化

**来源实现：**SemovixCandidateDrawer 展示增强、替代与延伸资源，并写明优势和局限；其统一“替换至方案”按钮和固定候选数据不等于已完成通用纳入流程。[S19](#src-s19)

**拟采用规则：**在现有候选列表中用一句话说明“这项资源对当前任务有什么用”，必要时展开差异。默认不复制多层优势/限制卡，不增加强制分类筛选栏。

| 候选用途 | 说明重点 | 动作边界 |
| --- | --- | --- |
| 补充当前目标 | 能补哪些维度或解释能力，还有哪些限制。 | 按现有评估、角色与选择规则纳入；可选下钻不自动成为计算输入。 |
| 替代当前资源 | 可以替代哪项，以及口径、粒度、时间是否有变化。 | 同口径按原选择规则处理；口径变化走需求重评，不把两个互斥指标同时加入 Core。 |
| 延伸到其他问题 | 与主题相关，但不是完成当前目标的必要资源。 | 先说明扩展的目标，用户明确扩展后重评；只浏览不改变方案。 |

候选用途、方案角色、纳入状态、使用权限是四个不同判断，不互相替代。用途说明不能重定义 Core、Conditional Support、Optional Drilldown 或 Partial Match；“部分匹配”也不是“已加入”。初期复用既有推荐理由、Coverage、Role 和选择状态生成说明，不强制新建用途枚举、存储表或排序器。

**最小验收：**用户能分清“补充 / 替代 / 另一个问题”；每个动作沿用原合同；获得查询权限或只查看候选均不会自动改变核心组合。未知适配关系写“当前尚未确认”，不以“高度相关”代替验证。

## 02｜统一交互原则：LUI 推进，GUI 承载

对话负责目标理解、澄清、控制、摘要与推进；GUI 承载需要浏览、选择、编辑或复查的结构化内容。用户可以通过自然语言或 GUI 动作推进同一任务，不在每个传统页面另加一个聊天框，也不把完整工作区塞进聊天。

### 2.1 什么应该出现在对话中？

| 内容 | 对话默认展示 | GUI 承载 |
| --- | --- | --- |
| 简单问答 | 直接答案及影响理解的必要限定；小结果可附少量数据行。 | 完整明细按需打开，不强迫用户为一个数跳页。 |
| 需要用户选择 | 一个主要决策及必要选项；确认后收拢。 | 复杂候选比较使用现有比较工作区。 |
| 方案或分析完成 | 摘要、未覆盖部分与一个主要下一步。 | 完整方案、结果表、因素明细与证据。 |
| 工具执行 | 正在做什么、成功/失败及对任务的影响。 | 代码和运行记录按需查看，不默认铺在聊天中。 |
| 工作产物 | 产物名称、摘要和可用操作。 | 报告预览或成果页面，不重复整份报告。 |

### 2.2 GUI 打开与更新规则｜V1.3 修正

**以用户是否已经表达结构化展示意图判断，不以有没有说“打开”作为唯一条件。**普通解释问题不自动切换右侧；“画出趋势图”“列出完整明细”“展开比较”已包含展示请求，不应在内容生成后再强迫用户重复点击同义入口。

| 用户意图或当前状态 | 对话行为 | GUI 行为 |
| --- | --- | --- |
| “为什么推荐它？”“这两项有什么不同？” | 先给摘要，必要时提供查看入口。 | 不因解释性提问自动切换。 |
| “打开完整字段”“展开比较这两个候选”或点击查看动作 | 简短确认对象，沿现有动作校验。 | 打开或更新对应工作区。 |
| “画出最近十二个月趋势图”“列出完整明细” | 沿现有确认与执行规则处理；真实内容就绪后说明结果。 | 这是明确展示请求，可直接呈现对应结构化内容，不重复要求“打开”。 |
| 用户只要求计算，未要求完整视图 | 对话给结果摘要与必要限制。 | 默认提供入口，不因计算成功抢占其他工作。 |
| 工作区已展示本次对象，用户仍在等待或查看它 | 当前回答或状态原位更新。 | 可更新同一对象；不把历史对象换成最新对象。 |
| 等待期间用户关闭面板、切换任务或明确转去其他对象 | 只提示原请求的结果已可查看。 | 尊重后续用户操作，不因旧请求迟到而重新打开或覆盖当前内容。 |
| 无权读取、对象失效、生成失败或组件不支持 | 说明真实限制，并给已有可行入口。 | 不打开伪结果、默认案例或错误对象。 |

展示意图不构成执行授权，也不跳过必要确认；结果未真实产生时不能展示演示内容充当完成。若用户明确要求本次再次打开对应对象，按新的请求处理，不受之前关闭操作永久限制。

关闭面板、切换展示 Tab、展开历史详情属于本地 UI 行为，不增加 Requirement Revision、不使 Ask Plan 失效、不触发搜索。选择资源和修改需求才走既有业务动作链。

本项细化 Surface Policy 的使用语义，不新增通用 NLU、路由服务或持久化“展示意图模型”。A 批次保持当前动作范围；新的展示语句支持随对应结果/工作区能力单独评审，不反向追加首批开发。

### 2.3 一轮只推动一个主要决策

需要澄清时，优先完成澄清，不同时推荐分析、报告、分享和周期任务。结果已就绪时，才提供当前有意义的下一步。聊天已有主要动作时，底部建议不重复它；没有合适建议就不显示。

用户已经明确选择过的范围和口径，不因进入下一能力而再次确认。只在缺少必要条件、存在实质歧义、范围发生变化或既有策略要求确认时打断；按原规则必须确认的受控动作仍执行。只读查看、图表/数据切换和历史展开不变成新的业务决策。

### 2.4 结果引用与多轮上下文继承｜V1.3 修正

旧消息打开口径、结果或报告时，必须定位该消息原本引用的对象与版本，不能静默打开“当前最新”替代历史内容。历史决定只读，已失效计划不能因为打开了旧结果而恢复执行。本节补充多结果追问的指代规则，不新增上下文中心或版本系统。

#### 2.4.1 先确定本次对象，再继承未变化的条件

| 当前信息 | 处理规则 |
| --- | --- |
| 用户明确写出资源、结果、时间或口径 | 优先按明确表达定位；无法唯一对应时只澄清该对象。 |
| 用户从某结果的“分析此结果”等动作发起 | 沿动作携带的既有对象引用承接，仍检查该对象是否存在、有效且可访问。 |
| 没有明确指名，但会话中只有一个可明确承接的对象 | 可以继承；需要时用一句话说明本次所用结果与口径。 |
| 多份结果均可能是“这个结果”，或文本与所附对象冲突 | 先问“基于哪一份结果？”；不默认取最新结果、最近打开的面板或任意资源。 |
| 只是打开历史结果 | 只改变查看对象，不自动覆盖当前需求、已选资源或执行计划。 |

当前正在阅读的面板可以帮助提示候选对象，但不能单独成为修改业务状态的依据。“同一任务”不等于同一结果；多份历史结果可以属于同一任务并保留各自范围。

#### 2.4.2 查看、解释与重新计算分别处理

假设本任务存在结果 A（在营可用床位）和结果 B（核定床位）：

| 用户行为 | 应有结果 |
| --- | --- |
| 打开 A | 查看 A 的原结果、口径与依据，当前任务不会自动变为 A 的计划。 |
| 明确问“A 为什么偏低？” | 围绕 A 分析，不能用 B 的公式或数据替代；原因证据不足按 6.3 处理。 |
| 同时存在 A/B，只说“这个结果为什么偏低？”且指代未明确 | 只澄清结果选择，不重新询问全部业务目标。 |
| 从 A 发起“只看最近三个月”并明确重新计算 | 使用 A 中已确认的口径与范围作为本次变更的参照，修改时间；走当前有效的需求/计划校验链生成新结果，不重启旧计划、不覆盖 A。 |
| 切换当前方案到 B，再查看 A 的依据 | A 的依据仍属于 A；不以 B 的最新定义重写历史引用。 |

对象确定后，仅修改用户明确改变的条件，继承其余已确认的对象范围、时间、口径与约束。可以提示：“本次基于在营可用床位结果继续，时间改为最近三个月。”不需要为这句摘要再增加一次同义确认。目标或口径仍有歧义时，沿既有澄清处理，不用默认值掩盖冲突。

#### 2.4.3 权限信息可保留，授权结论不得永久继承

历史权限信息只用于说明当时条件，不能代替当前读取或执行时的授权判断。查看历史结果按既有当前访问策略处理；新运行重新校验所需资源与动作。权限变化不改写历史结果的实际输入，也不允许用缓存或历史授权快照继续访问被禁止的内容。

所需对象引用与历史上下文应由既有 Task、Result/Artifact 和服务提供；缺少明确引用时给出澄清或不可用状态，不引入第二套浏览器业务真相。上述规则用于后续入口与短追问评审，不能仅从参考页面推断当前代码已全部支持。

> 来源说明：参考仓库展示了答案、口径、执行记录和资源入口；多对象承接规则来自本轮审查后的 Semovix 设计，不是对参考实现历史绑定能力的背书。[S04](#src-s04)[S06](#src-s06)[S07](#src-s07)[S15](#src-s15)

### 2.5 从回答定位对象，不让“查看”变成“选择”｜V1.1 细化

| 用户动作 | 定位对象 | 业务状态影响 |
| --- | --- | --- |
| 查看候选字段 | 该回答引用的资源及当前允许查看的字段元数据。 | 仅查看；不把候选纳入方案，不默认为分析输入。 |
| 查看本次计算口径 | 该结果引用的指标定义或分析计划版本。 | 不改成当前最新定义，不重算。 |
| 查看执行依据 | 与该结果对应的运行记录；有权且确有 SQL/执行信息时才展示。 | 不以展示 SQL 触发执行，不拼接默认 SQL。 |
| 确认使用候选 | 当前有效候选及其预期方案角色。 | 走现有 TaskAction、版本和权限规则。 |
| 修改需求或口径 | 已明确的本次任务范围及正式修改入口。 | 走原失效、重组和确认链，不直接编辑历史结果。 |
| 基于某份历史结果重新计算 | 用户明确指定的结果及其原口径、范围。 | 参照该结果准备新的有效计划；不恢复旧计划执行、不覆盖原结果。 |
| 保留结果、切换图表/数据 | 现有结果引用或该结果的本地展示方式。 | 不改变 Requirement、核心资源或 Ask Plan。 |

打开或更新右侧前，使用当前对象引用与现有门禁判断。对象缺失、不可访问或历史版本不可取得时，显示明确状态，不回退到任意资源、最新 SQL 或默认案例。查看动作不能将候选变成已选资源；已明确选中的资源继续遵守原上下文继承规则。

**元数据、样本、结果分别处理。**查看字段遵循元数据权限；样本预览遵循样本访问规则；查询、复制受保护内容、下载和分享遵循各自动作的既有授权。不以“已脱敏”文案或前端隐藏按钮代替服务端裁剪与授权。

本节与 2.4 一起细化既有动作的对象定位，不要求新增 SQL 编辑器、预览 Surface 或统一对象路由系统。[S15](#src-s15)

### 2.6 展示密度和视觉边界

沿用 Semovix 当前浅色、高留白、中文优先的执行页母版。不搬运参考仓库的常驻三栏、黑色大块证据区、全部功能 Tab、固定轮次条及嵌套大卡片。

简单答案不必跳页，复杂结果不必全部留在聊天。默认将“答案、必要限定、一个主要查看/推进动作”放在对话中；完整资源列表、依据和结果按 2.2 的展示意图承载。技术字段、公式和结果允许按现有权限复制，但不扩大可访问内容。颜色只辅助状态，不能代替明确标签。

“一项关键限定”“三行结果”“一至两行摘要”只能作为初始密度目标，不是删减业务含义的上限。多项限制都会改变结论时，必须就近说清；压缩重复说明和技术细节，不截掉时间、人群、口径或未验证结论。也不要求为了保留事实/判断/限制而各新增一张卡。

### 2.7 当前资源：业务含义、时间与粒度优先｜V1.2 细化

**来源实现：**discover-0815 的当前资源页展示衡量/业务对象、时间语义、记录粒度、业务域、责任单位与关键字段，并区分指标口径和资产字段的标题。[S18](#src-s18)

**拟采用阅读顺序：**资源身份与业务含义 → 本次方案用途 → 时间、粒度与覆盖 → 当前操作状态 → 按需字段或关系详情。指标优先解释正式定义、单位与维度；数据资产优先解释记录主体和记录粒度，不强行使用同一种详情文案。

资源自身的定义、版本和粒度，与“在这次任务中的角色”分区表达；后者从当前方案读取，不写回资源永久属性。首屏只显示与当前操作有关的权限摘要，完整动作状态按需展开。字段可查看不意味着样本可预览；质量、认证、更新时间没有真实返回就不补默认值。

仅调整现有资源/字段工作区的阅读次序，不新增资源中心、常驻权限矩阵或重复的上下文卡。无权、缺失或历史引用不可取得时沿用 2.5 的真实状态，不回退到默认资源。

### 2.8 问数交接摘要：使用项、未使用项与结论边界｜V1.2 细化

**来源实现：**参考仓库的 ExecutionSelection 与 ConfirmedContextCard 展示 selectedItems、excludedItems、scope、limitations 和版本；但选择构造会依据可用状态纳入资源，App 承接后立即生成固定结果。只借鉴摘要内容，不搬运选择算法或自动完成逻辑。[S20](#src-s20)

**拟采用规则：**从现有 Data Solution、当前明确选择与 Ask Plan 派生交接说明，不另建 ExecutionSelection 主对象。区分“计划拟使用”与“实际运行已使用”；交接时只能说准备了哪些输入和范围，执行成功后才可声称已使用并得到结果。

| 展示位置 | 内容 |
| --- | --- |
| 对话 | 本次分析范围、核心使用摘要及会改变结论的必要限制；需要时提供“查看本次计划”。 |
| 现有计划/方案工作区 | 拟使用资源及作用、重要未使用项及原因、明确时间与口径、限制和执行前校验状态。 |
| 分析结果/报告 | 实际运行使用的输入、范围与相应限制；不得从原始目标标题推断已完成范围。 |

例如：“本次按街镇比较人口规模与整体热线诉求分布，不识别实际老年诉求人；执行前仍需检查所选资源及关联条件。”使用这类摘要不意味着再添加一次资源确认；已有明确选择直接继承，需要改变问题时才按 1.6 确认。

交接沿用 1.6 的三个判断：原目标可以仍为部分覆盖，本次已确认的子问题可以在必要条件满足后执行；运行成功只说明该次范围完成。统一避免无范围的“分析全部完成”。从明确资源直接进入问数时，也只派生必要的输入和限制摘要，不为生成摘要而强迫用户重新走找数页面。

只对当前用户有权获知、且与该方案有关的未使用项解释原因；不罗列所有未选候选，更不泄漏隐藏资源。可查询不等于已选择；可选下钻不等于核心输入；权限申请通过不自动扩大方案。需求变化后依照既有规则使旧计划和未完成决定失效，历史交接摘要保持原范围，不静默改写。

### 2.9 权限申请：带入任务背景，复用原服务｜V1.2 后置细化

**来源实现：**权限抽屉带入资源、用途和期限，展示提交后的申请状态及策略入口；实际提交由计时器模拟、申请号固定，不能作为真实权限服务使用。[S21](#src-s21)

**拟采用规则：**用户触发既有申请动作后，带入目标资源、申请动作和当前任务用途，用户只补充合同要求且尚缺的信息。用途、期限及可选期限由现有权限服务决定，不复制固定 7/30/90 天选项或增加新的审批模型。

提交中、申请已提交、已授权和被拒绝分别呈现；申请成功不等于授权成功，授权成功也不自动纳入分析。去重、批量处理和失败恢复沿用原有规则。权限提示使用真实动作名称，不能把元数据、样本、查询和导出都称为“查询权限”。

申请过程中可继续原本有权且满足当前已确认范围的工作；如果缺少关键输入，不能仅因按钮可用就计算。改为不同问题仍按 1.6 明确确认。策略说明仅在有权读取真实适用策略时提供，不以固定“已脱敏”说明作合规背书。无服务承接时保留现有申请入口，不新增抽屉或宣称已提交。

本节随原权限交互与服务单独排期，不属于 A，也不阻塞答案、依据或成果展示的独立交付。

## 03｜A-01 智能滚动与阅读位置保护

### 3.1 来源实现与当前差异

AgentThread 以“距离底部约 100px”判断用户是否正在跟随最新内容：接近底部时自动滚动，上翻时保留位置并显示“有新内容”。Semovix 固定基线的执行页则在 turns 或 runtimeStatus 更新时直接滚动到底部。[S01](#src-s01)

### 3.2 拟采用的完整逻辑

| 触发条件 | 页面行为 | 不应发生 |
| --- | --- | --- |
| 用户靠近底部，新消息到达 | 继续跟随最新内容；滚动仅作用于对话容器。 | 带动整页或右侧工作区滚动。 |
| 用户正在上翻阅读，新消息到达 | 保留阅读位置，显示一个“有新内容”提示。 | 自动抢回底部、重复弹提示或制造未读数量。 |
| 点击“有新内容” | 滚到底部，清除提示，恢复跟随。 | 提交 Turn、重跑任务或切换 Surface。 |
| 用户手动回到底部 | 清除提示并恢复跟随。 | 要求用户必须点提示才能恢复。 |
| 用户发送新消息 | 展示本次发送内容并进入跟随。 | 把草稿或上次任务未读状态带入新任务。 |
| 用户展开历史详情或右侧面板 | 保持当前阅读锚点；布局变化不算新消息。 | 因组件展开而误显示“有新内容”。 |
| 切换任务 | 清除旧提示；按现有恢复行为定位新任务。 | 跨任务保存一套新的滚动历史数据库。 |

### 3.3 实现边界

只维护本地 UI 状态：是否靠近底部、是否有新内容及 DOM 引用。约 100px 可作为初始阈值，属于展示参数，不作为业务合同。不要把滚动状态写入 Task、不要增加服务端字段，也不对每次渲染都强制平滑滚动。

运行状态更新只在确有用户可见的新内容或高度变化时参与判断，不能因为对象引用变化就打断阅读。决策卡收拢时同样需要保持用户阅读位置。

### 3.4 首批验收

A01-1：上翻后连续收到消息和运行状态更新，视口不被拉回底部，提示最多一个。
A01-2：点击提示和手动回到底部均能恢复跟随；切换任务不残留上一任务提示。
A01-3：展开历史详情、调整右侧工作区不会误触发新消息提示；不产生任何业务事件。

## 04｜A-02 已确认决策收拢为只读摘要

### 4.1 来源实现与吸收目标

参考仓库在指标选择完成后，将候选卡直接替换为一行“已使用正式指标口径”；周期任务确认后也采用紧凑摘要。Semovix 已有决策锁定与失效机制，但固定基线中已确认选项仍以完整控件布局展示。[S02](#src-s02)

本项只减少历史控件占用，不改变什么时候需要澄清，也不把既有单选/多选交互改成点击即执行。

### 4.2 状态与默认呈现

| 状态 | 默认呈现 | 允许操作 |
| --- | --- | --- |
| OPEN｜待选择 | 问题、必要选项与一个提交动作。 | 本地选择；显式提交后才推进 Task。 |
| 提交中 | 保留所选内容，显示提交中并禁用重复提交。 | 不收拢为已确认，不提前显示成功。 |
| RESOLVED｜已确认 | “已确认：所选业务值”的紧凑摘要。 | 可展开只读详情；不重新提交历史决定。 |
| STALE｜已失效 | “当前需求已变化，此选择已失效。” | 只读复查；不得保留继续按钮。 |
| 提交失败 | 保留选择及错误信息，恢复可提交状态。 | 通过原动作重试，不创建第二套决策状态。 |

### 4.3 交互细则

摘要以一至两行自然排版为目标，不采用固定高度截断。选项很多时可显示前几项与“等 N 项”，展开后提供完整只读内容；不得丢失决策含义。默认不显示内部 optionId、questionId 或状态枚举。

是否已确认、是否失效只读取 Task 中的 resolution；组件本地仅保存展开/收起状态。服务端返回 RESOLVED 后才收拢，失败后不隐藏错误。刷新重挂载仍依照 Task 呈现，不以本地 submitted 充当业务事实。

展开只读详情不产生 Turn、不改变 Revision、不打开右侧。用户需要修改时，通过当前任务上下文或现有修改入口处理，不能解锁历史问题。现有 STALE 行为和已确认历史保存规则保持不变。

### 4.4 首批验收

A02-1：提交成功才收拢；失败保留选项与重试；刷新后仍正确展示已确认结果。
A02-2：历史 RESOLVED/STALE 不能再执行；展开/收拢不改变 Task、方案或计划。
A02-3：只读详情能查看完整选择，收拢不造成当前阅读位置突然跳转。

> 执行进度完成后的收拢属于 B-02：需要真实事件才有步骤可收拢。A-02 不新增进度条，不要求接 SSE，也不伪造步骤。

## 05｜A-03 基于现有动作的下一步建议

### 5.1 来源实现

来源按阶段、区域与指标生成建议，界面最多显示三项。吸收随任务变化的方式，不搬固定阶段、预设场景或提示词路由。[S03](#src-s03)

### 5.2 最小处理链

```text
读取当前 Task 与既有候选动作
→ 按当前状态、对象存在性及既有门禁过滤
→ 与本轮主要动作去重
→ 按固定业务优先级保留 0–3 项
→ 点击后再次校验并进入现有动作链
```

首批只展示已经实现的 typed action，点击传原 actionCode 与对象 ID，并经原门禁执行，不从 label 反推动作、不绕回自然语言解析。自由追问示例只填入输入框供用户提交，不列入首批自动执行建议。

### 5.3 状态优先级

| 当前情况 | 建议策略 | 避免的行为 |
| --- | --- | --- |
| 存在待回答澄清 | 以当前决策为主；必要时只保留一个补充条件入口。 | 同时推荐分析、分享，跳过当前决策。 |
| 变更操作进行中 | 暂停变更型建议；不改变已允许的本地查看行为。 | 新建议造成并发写入或重复提交。 |
| 方案已就绪 | 优先当前方案/比较等已实现动作；分析仍走原门禁。 | 为了显示三项而添加未实现能力。 |
| 部分覆盖或当前有缺口 | 优先查看缺口、调整需求或原有补充路径。 | 只因存在 Core 就暗示完整目标已经完成。 |
| 权限未就绪 | 仅展示原有可申请、可调整方案的动作。 | 将可发现直接视为可查询。 |
| 对象或计划已失效 | 不再推荐引用旧对象的动作。 | 沿用旧消息中的过期对象或旧 Plan。 |

### 5.4 呈现与实现边界

建议仅位于最新有效回答后，与 Result Brief 的主动作去重；不复制到历史消息。标签表达动作及对象，例如“查看当前方案”；无合适建议则隐藏。

使用轻量函数组合现有动作、canExecuteTaskAction、Ask Handoff 与 Surface Policy，不新增服务、排序模型、数据库或动作协议。

### 5.5 首批验收

A03-1：建议随当前状态变化、最多三项且无重复；待澄清时不出现绕过决策的动作。
A03-2：渲染后资源/权限发生变化，点击仍被现有门禁阻止；没有新增语义路由或业务状态副本。

## 06｜B-01 答案优先、短追问与依据按需查看

### 6.1 来源与边界

aloudata-demo 的 MetricAnswerBlock 先显示周期、范围、指标和值，再显示紧凑结果行及“查看指标口径 / 为什么变化”；ContextPanel 与 EvidenceBlock 分别承载定义、执行记录和因素依据。[S04](#src-s04)

find-ask 用 CompactCitationDocs 展示来源索引与摘录，用 CustomChart 和 tablePreview 展示图表与数据。其来源切换、图表及表格值得参考，但当前主要是在同一条消息中分别展开，不等于已经实现下面的统一轻量交互。[S12](#src-s12)[S13](#src-s13)

discover-0815 进一步展示 Source Facts、Derived Assessment 和 AI 解释，并区分语义关系、资源绑定、分析关系候选与已验证查询关系。本版借鉴其分层表达，不迁移固定事实状态、关系编号或演示执行。[S18](#src-s18)

本节保留原 B-01 编号，按三份来源细化拟采用规则；不搬入预设数值、固定候选、固定匹配度或“全面可信”保证。

### 6.2 结果展示规则｜V1.3 修正

对话使用“直接答案 + 影响结论的必要限定 + 可选少量数据行 + 必要入口”。三行结果可以作为初始密度目标，不是后端截断或强制跳页标准；简单结果直接回答，复杂对象在现有工作区承载。用户已要求画图、列完整明细时，按 2.2 展示，不重复要求“打开”。

正式指标与本次分析计算分别标明，结果摘要来自对应 Artifact，而不是从展示行数推断发现数量。没有验证结果时写“待验证”，没有证据时写“当前依据不足”；不能用推荐置信度替代数据依据，也不展示模型内部思维链。成功文案限定到本次实际执行范围，原目标有未覆盖项时仍保留说明。

正文尽量无大卡片边界，一个阶段只保留一个主要结果块。必要限制不因“一项”“三行”等密度建议被删除；完整证据、字段或运行记录则按需展开，避免在对话与 GUI 重复。

### 6.3 短追问与分析能力边界｜V1.3 修正

#### 6.3.1 先明确引用对象，再处理变化部分

| 用户输入示例 | 任务处理 | LUI / GUI 行为 |
| --- | --- | --- |
| 只看最近三个月 | 先按 2.4 明确本次承接对象，再仅修改时间，继承其余已确认条件。 | 对象不唯一时只澄清该项；确定后说明本次变更，按原规则失效和重算。 |
| 换成核定床位 | 替换床位口径，不追加第二个床位 Core。 | 展示新口径摘要，不默认切换无关工作区。 |
| 为什么这些街镇偏低？ | 引用明确结果进入分析；先区分描述差异、分解差异与证明原因。 | 只说证据支持的发现；需要额外数据时补充找数，不预设因果关系。 |
| 这两个资源有什么不同？ | 解释性问答，不改变当前需求。 | 对话给摘要，提供比较入口。 |
| 打开完整结果 / 查看本次口径 | 定位该结果原本引用的对象与版本。 | 由 Surface Policy 打开或更新现有工作区。 |
| 画出趋势图 / 列出完整明细 | 已是明确展示意图；根据现有数据或真实执行结果生成对应视图。 | 按 2.2 直接承接，并尊重用户等待期间的新操作。 |

上述为目标行为示例，不要求 A 批次增加语句覆盖。真实模式依赖后端结构化意图与结果，前端不继续堆积场景正则；直接进入以已有能力为前提，不因文档写入就宣称已经支持。

#### 6.3.2 描述、分解与因果/预测不是同一种分析

| 请求层次 | 可以做什么 | 进入条件 | 条件不足时 |
| --- | --- | --- | --- |
| 描述已有结果 | 解释当前比较、排名、趋势及已计算差异。 | 明确且可访问的对应结果、口径与范围。 | 先澄清所指结果；没有结果不编数，沿已有问数路径取得。 |
| 进一步分解 | 按已有维度下钻、比较分组，或用明确方法计算差异贡献。 | 对应数据、维度与可用计算方法；需要新增查询时经过现有执行门禁。 | 说明缺哪类支撑，按需返回找数；不将分解结果直接叫作原因证明。 |
| 因果、预测或行动建议 | 在明确方法、输入、假设和验证条件下回答相应问题。 | 对应方法与服务已明确具备并单独验收；不能只靠一张查询结果表。 | 当前证据不足就说明不能确认，不虚构原因、未来值、建设规模或最优决策。 |

本方案不承诺已具备通用因果分析、预测或优化引擎，也不要求现在新增这些能力。用户问“为什么”时，不应一概拒绝：先说明现有结果能确认的差异，再说明尚不能解释的原因。提出待验证思路时明确其性质，不把假设写成已发现原因。

示例：某街镇每千名老人床位数低于比较基准，可以描述其相对水平；若已有有效人口和床位数据，也可以在明确方法下进一步分解。**仅凭该比率不能直接证明设施建设不足，更不能直接给出应新增的床位数。**

推荐回答方式：“当前结果能确认该街镇在营可用床位相对水平较低；现有数据还不足以判断原因或新增规模。实际服务使用等支撑是否需要补充，应围绕你要回答的具体问题继续评估。”这是一条边界示例，不意味着新增完整业务 Fixture。

#### 6.3.3 补数据后返回当前问题

分析发现缺数据时，只补充完成该问题所需的资源；沿用当前已确认的对象、范围和口径。新候选先评估，不自动纳入，涉及范围改变按 1.6 明确接受。补充未成功时保留已有描述性结果及限制；不能用旧结果或另一份口径的结果证明新的分析结论。

### 6.4 依据、适用判断与结论支撑｜V1.3 修正

```text
第一层：结论摘要及关键限制（对话）
第二层：指标、数据与因素明细（GUI）
第三层：具体口径、版本、证据或执行记录（按需查看）
```

关键限制不能仅藏在折叠区域。例如缺少实际服务使用数据会改变结论边界，应在摘要中明确；完整证据列表则无需首屏展开。技术代码默认放在执行记录中，不在聊天和右侧重复展示。


#### 6.4.1 同时分清“资料说了什么”和“这次任务如何使用”

上面的三层是信息展开顺序；下面三类是内容性质，二者不要求对应三张卡片。参考组件把事实源、推导评估与 AI 解释分区，本方案将可核验事实与适用判断分开，并让限制与相关判断就近呈现，而不是新增一块泛化的“AI 已验证”。[S18](#src-s18)

| 内容性质 | 应表达什么 | 必要边界 |
| --- | --- | --- |
| 已登记事实 | 来源实际提供的资源定义、口径、版本、记录粒度、业务对象或治理状态。 | 按来源原意展示；“已登记”不等于本轮再次验证，未返回的信息不补。 |
| 对当前任务的适用判断 | 依据这些事实，当前资源能覆盖哪项需求、为何推荐或为何不足。 | 明确这是任务相关判断，可回到事实与需求；不能将“适用”写回成资源永久属性。 |
| 限制与待验证项 | 当前未覆盖的目标、未验证关联、时间或口径差异，以及不能推出的结论。 | 影响答案的限制留在摘要旁；没有证据不显示“已验证”，存在分歧不静默合并。 |

示例：“指标定义表明其按街镇统计 60 岁及以上常住人口”是来源事实；“适合本次街镇人口规模比较”是当前判断；“不能识别热线工单的实际老年诉求人”是结论边界。该示例用于说明内容性质，不代表生产资源已完成读取。

短问“为什么推荐它？”可以在一段文字中表达事实、判断和必要限制；只有用户明确查看详细依据时再展开引用。AI 解释是对已有信息的可读表达，不是新的证据来源，也不展示模型内部推理链。

#### 6.4.2 业务关系、资源绑定与查询验证分别解释

| 当前证据只支持 | 可采用的表达 | 不可推导的表达 |
| --- | --- | --- |
| 业务对象关系 | 业务定义中存在该关系。 | 这两张表已经能直接 Join。 |
| 资源与对象的绑定 | 已登记该资源支撑对应业务对象。 | 两边各自绑定对象就等于已有跨资源连接。 |
| 本次分析的组合可能性 | 可围绕已知维度评估组合，具体关联仍待验证。 | 字段同名、同粒度或都有街镇维度，就已证明关联正确。 |
| 针对明确版本、范围的查询验证结果 | 该关联在所述范围和条件下已验证。 | 自动扩大为所有版本、所有任务都已确认。 |

继续消费 Semovix 既有关系类型、验证状态和 Runtime 结果，不引入 R1—R4 编号体系，不增加 Join Planner，也不改变已冻结的执行门禁。权限可用、语义相关与技术关联可执行分别判断。证据不足时返回待验证，不用强保证标题覆盖正文中的限制。

**服务边界：**本版只是规定怎样呈现已有事实、判断与限制；如果服务不能返回对应依据，就说明“当前依据不足”，不要求前端重做语义评分、证据计算或治理算法。

#### 6.4.3 引用存在，不等于支持当前结论｜V1.3 修正

**来源可定位与结论被支持是两件事。**某段说明有引用，不代表其中每个数字、原因和建议都被该来源证明。阅读器只展示来源；回答和分析需要继续核对来源与具体主张的对应关系。

| 当前主张 | 需要的支撑 | 不能替代它的内容 |
| --- | --- | --- |
| 本次指标按什么口径计算 | 实际引用的定义/计划、适用时间与范围。 | 另一版本定义、名称相近的指标说明。 |
| 哪些街镇低于本次比较基准 | 对应运行结果和本次基准规则。 | 仅有指标定义，或把展示行数当作偏低数量。 |
| 差异在某维度上如何分布或贡献多少 | 使用对应数据、明确方法得到的分解结果与适用条件。 | 相关文档标题、模型编写的原因列表。 |
| 某因素导致变化或应采取某项行动 | 与该因果/行动判断对应的方法、证据及假设边界。 | 单次相关性比较、一个偏低比率、通用制度摘录。 |

指标定义能够说明分子与分母，不能单独证明某地区为什么供给不足。来源只支持部分主张时，结论应收窄并保留限制；来源之间有实质分歧时分别说明，不由措辞润色消除冲突。不能用报告篇幅、引用数量或“已登记”徽章代替结论核验。

实施时消费已有证据引用与运行结果，在相应分析验收中人工核对关键主张即可；本轮不新增逐句引用数据库、自动证明系统或通用事实核查引擎。未获得所需证据时给出“当前不能确认”的边界，不让前端补造证明。

### 6.5 紧凑多来源依据：清单、单份摘录、原文定位｜V1.1 细化

**默认形态：**对话只显示本次实际引用来源的简短摘要和“查看依据”。来源数量按实际可展示的引用计算；没有来源时不凑数。关键限制仍留在答案旁，不藏进依据面板。

```text
本次依据：指标定义、统计说明等已引用来源
    ↓ 用户明确查看
来源清单
    ↓ 选择一项
名称 / 版本 / 章节或可用定位信息
    ↓
与本次回答相关的摘录或定义
    ↓
查看原文或对应定义
```

默认只采用“紧凑清单 + 当前来源详情”一种交互；来源很多时清单可滚动。不同时提供画廊、手风琴、选项卡和全貌弹窗。技术承载复用现有口径、证据或对象详情容器，空间不足时采用现有展开能力，不创建独立证据中心。

| 依据类别 | 展示内容 | 不能混淆的内容 |
| --- | --- | --- |
| 指标口径 | 名称、实际引用版本、定义与范围。 | 正式指标不等于本次临时计算。 |
| 文档依据 | 文档名称、版本、章节/页码或其他真实定位、相关摘录。 | 不把所有企业文档叫“官方法规”。 |
| 数据结果依据 | 对应结果及必要任务/运行引用。 | 查询结果不等于文档摘录。 |
| 关系依据 | 当前确认状态、关系说明与可取得的证据。 | 语义相关不等于技术 Join 已确认。 |

| 状态或操作 | 拟采用行为 |
| --- | --- |
| 来源可读取 | 展示已返回的定义/摘录；只在原文目标确实存在时提供定位入口。 |
| 缺少页码或版本 | 不编造页码、不自动写“最新版”；可用其他真实定位，没有则说明未提供。 |
| 不同来源存在适用范围或版本差异 | 分别保留来源和限制，不把差异静默合并成一致口径。 |
| 读取失败、无权或引用已不可用 | 显示该项真实状态，不换成其他文档，不扩大到整库检索结果。 |
| 切换来源或复制摘录 | 保持当前任务，不重算、不改计划；复制仅针对当前有权获取的内容。 |
| 打开历史回答的依据 | 定位原回答引用版本；版本不可取得时明确说明，不使用最新版本冒充。 |

**服务进入条件：**来源服务能返回可引用的实际内容与定位，且已由现有权限机制控制读取。来源 ID、版本、定位、摘录等是展示所需语义，不是要求另建一套数据库或索引。缺少这些条件时保留已有依据入口，不生产带虚构引用的完整阅读器。

参考实现中的固定“匹配度 99.4%”、默认“最新生效标准”和模拟法规摘录均不采用；引用相关程度不能替代内容真实性或授权判断。阅读器能打开来源也不能替代 6.4.3 的结论支撑判断。[S12](#src-s12)[S16](#src-s16)

### 6.6 同一结果集的图表与数据视图｜V1.1 细化

**拟采用规则：**在现有结果工作区中对同一份已产生结果提供“图表 / 数据”两种视图，而不是在聊天和 GUI 各展开一套图表、表格及 KPI。工作区何时打开由 2.2 的展示意图决定，不因为返回字段中存在 chart 就自动切页。

| 场景 | 默认呈现 | 规则 |
| --- | --- | --- |
| 单个指标或少量对比 | 对话直接回答，可带少量数据行。 | 不要求用户为一个数字打开工作区。 |
| 时间变化 | 有对应数据时，在结果工作区优先显示趋势图。 | 时间和单位来自结果，不由模板推断。 |
| 街镇/部门比较 | 优先适合该结果的比较图。 | 不把不同单位强行放进同一数值尺度。 |
| 需要精确核对 | 切到“数据”，查看同一结果的数据行。 | 与图表的口径、时间、筛选和舍入规则一致。 |
| 无数据或不支持图表 | 保留真实空态或数据表。 | 不用另一张演示图替代，不把未知图表类型静默渲染成错误图。 |

“图表 / 数据”切换仅改变展示，不提交 Turn、不重新查询、不改变 Requirement Revision。确需加载更多结果行时，只读取同一结果的已有分页内容，不改成一次新分析；尚未具备相应服务时不显示虚假的完整数据入口。

当前批次不新增自由图表编辑器、仪表盘布局编辑、额外预测模型或任意图型切换。图表类型选择以现有组件能力和结果结构为限。

来源中的 Recharts 图型渲染与数据表可以作为组件参考；“同一结果集、两种视图”的规则是本方案拟采用设计，不是对源代码已经实现该切换的描述。[S13](#src-s13)

### 6.7 B-01 独立验收

| 检查项 | 通过标准 |
| --- | --- |
| 答案与结果 | 摘要来自对应 Artifact；没有明确的业务统计值时使用中性总结，不从结果行数推断结论。 |
| 短追问 | 先确定本次引用对象，仅修改用户明确改变的条件；只读查看/解释不修改需求或已选输入，确需补数据则走原链。 |
| 多来源依据 | 当前来源、摘录与原回答一致；缺版本、无权或失效时有真实提示。 |
| 图表/数据 | 两种视图引用同一结果；切换不重算、不改变任务版本。 |
| 对象定位 | 点击资源、口径、运行依据时定位正确对象；多结果指代歧义只澄清对象，查看不等于确认选用。 |
| 事实与判断 | 来源事实和当前任务适配判断可区分；缺信息不补默认可信值，限制不被解释文案掩盖。 |
| 关系表达 | 业务关系、绑定与查询验证不混淆；展示结论不超出已有证据的版本和适用范围。 |
| 分析能力边界 | 描述、分解与因果/预测分开；没有对应方法和证据，不产生确定性原因或行动数值。 |
| 主张与证据 | 关键数字和结论有对应结果/来源支持；仅有引用标题不视为结论通过。 |
| 展示意图 | 已要求画图/完整明细时不再重复要求打开；用户已切换工作区时不被迟到结果覆盖。 |
| 部分完成文案 | 本次子问题执行成功不宣称原目标完成；原有缺口继续可见。 |

本节每一项可独立实施与验收，不要求为了做结果展示而同时接完多文档、报告或分享服务。

## 07｜B-02 真实运行反馈与 B-03 报告预览

### 7.1 运行过程：就地更新，完成后收拢

来源实现：ExecutionProgressBlock 用一个 Block 更新步骤，完成后自动折叠；但参考诊断 Handler 通过定时等待推动演示步骤，不能把该计时机制当成真实执行进展。[S05](#src-s05)

| 执行情况 | 拟采用行为 |
| --- | --- |
| 只有总状态，没有步骤 | 显示单行“正在处理当前分析”等业务状态；不编造步骤数量。 |
| 有可验证的阶段事件 | 在同一个运行块更新当前步骤，避免每次更新新增聊天消息。 |
| 正常成功 | 按本次计划范围给出完成摘要并默认收拢，允许只读展开；原目标缺口保留，用户正在查看详情时不强制收起。 |
| 失败、取消或部分完成 | 保留真实状态、影响和已有恢复动作；不得显示全部完成。 |
| 重试 | 展示当前一次运行的状态，保留原失败历史，不偷偷覆盖其结果。 |

接入条件：运行服务能提供稳定运行标识及可信状态。首批不为此新增 SSE；以后采用流式事件时，通过现有适配层映射，不复制参考仓库的 EventHub/TaskStore。超时或断线只能表示状态未知/连接中断，不能当作业务成功。

### 7.2 报告：独立产物，聊天只保留入口

来源实现：ArtifactBlock 通过 artifactId 预览和下载，App 获取报告再打开预览；服务端示例报告含范围、指标、摘要、发现、证据与限制，但主要为 Mock 内容及内存存储。[S06](#src-s06)

```text
Analysis 形成可引用产物
→ 对话显示名称、摘要和“查看报告”
→ 按产物 ID 与既有访问规则获取报告
→ 在现有产物预览承载中打开
→ 返回后保留任务与阅读上下文
```

报告应注明所用范围、时间、定义/计算口径、数据依据、生成时间、限制和来源标识；没有的字段不能凭模板填出。采用 1.6 的部分范围或相近问题后，标题、摘要与结论均以实际执行范围为准；原目标未完成的部分不得被写成完成。依据 6.3—6.4，报告不能把描述性结果改写成因果证明或把待验证思路改成确定建议。预览缺失或加载失败应显示可信错误，不回退到其他报告或构造占位报告冒充成果。

下载仅在服务提供可下载完整内容且当前用户有权获取时出现。结构化 JSON 不是完整 HTML 文件；没有 HTML 导出就不伪造下载。若需预览服务端 HTML，必须采用受限、安全的渲染方式，避免把产物脚本运行在工作台上下文。

### 7.3 分开交付

任务内成果保留、报告预览、精选分享可以分别交付，没有强制先后依赖。用户不必先“保留”才能预览或分享已有结果；也不必具备报告生成能力才能保留一份已有分析结果。

报告预览可先独立实现；精选分享需另行满足 B-03 的权限与服务条件。没有报告服务时，只保留已有结果工作区，不为一张入口卡新建产物中心。

## 08｜B-03 任务内成果保留与精选分享

### 8.1 来源与本版整合方式

aloudata-demo 允许选择业务结果 Block，服务端从任务取出并过滤后生成只读分享；这体现“交付成果而非整段聊天”，但不能据此证明生产授权、脱敏、撤销或到期能力已经完成。[S07](#src-s07)

find-ask 在消息图表下提供“钉选到看板”，由前端 pinnedCharts 保存图表、摘要等内容，右侧允许查看和移除；其导出简报按钮是提示性实现，不是实际报告生成。[S14](#src-s14)

本版吸收二者的用户工作方式，统一放入 B-03：先允许保留有价值的任务结果，后续按需要预览、生成报告或分享。保留不等于创建企业看板；选择图表不等于结果可以被公开分享。

### 8.2 三项能力独立交付

| 子项 | 用户目的 | 最小承接条件 |
| --- | --- | --- |
| 任务内成果保留 | 多轮分析中保留值得回看的结果。 | 已有可稳定引用并受访问控制的 Result/Artifact，以及任务持久化承接。 |
| 报告预览 | 查看已经形成的报告。 | 实际报告内容、读取授权及既有预览方式；详见 7.2。 |
| 精选成果分享 | 把选定成果及必要上下文交给他人。 | 服务端分享创建、读取授权与既有生命周期承接。 |

这三项不是一条强制流水线。任一项缺少服务，不应阻止其他具备条件的子项交付，也不能因为入口已画好就显示“已生成”“已分享”。

### 8.3 保留到本次任务成果｜V1.1 新增待评审

用户动作名称建议为“保留到本次任务成果”，已保留时显示“已保留”。查看与移除入口位于现有任务成果承载中，不新增“决策看板”一级菜单、独立 Dashboard 页面或布局编辑器。

```text
结果已实际生成
→ 用户选择“保留到本次任务成果”
→ 使用既有结果 ID/版本引用保存关联
→ 当前任务可再次打开该历史结果
→ 用户按需选择其中内容预览、报告或分享
```

| 触发条件 | 拟采用行为 | 不应发生 |
| --- | --- | --- |
| 首次保留 | 关联已有结果引用并反馈“已保留”。 | 重新计算、重新生成图表数据或改变当前 Core。 |
| 同一结果再次保留 | 按同一结果引用/版本去重，保持一项。 | 因按钮连点复制多个成果。 |
| 明确移除 | 取消本任务中的保留关联。 | 删除原始结果、历史消息或已独立创建的分享。 |
| 保留后继续追问 | 原结果保持原时间、范围与口径；新结果独立产生。 | 把新图表数据写进旧结果。 |
| 打开历史保留项 | 按原引用读取，并展示必要上下文。 | 改读“当前最新”，或将历史结果自动设成新计划输入。 |
| 结果读取失败或权限不允许 | 显示现有授权规则下可显示的不可用状态。 | 用浏览器缓存绕过权限，或替换成其他结果。 |
| 只点击“保留” | 在当前区域给轻量反馈。 | 强制展开或切换右侧；只有明确“查看已保留成果”才打开。 |
| 切换任务 | 只展示目标任务的成果关联。 | 将其他任务的 pinnedCharts 静默带入。 |

保留以现有 Result/Artifact 为基本单元，不自由拼接不同运行的半张图或去掉限制的一段结论。结果应能展示其标题、时间范围、业务口径、生成时间和来源标识；只有服务已返回的字段才展示。

需要持久化的是既有成果的任务关联，而不是另复制一份浏览器图表作为业务真相。具体承接字段在该子项实施时沿用现有任务/产物合同；当前资料不足以确认所有所需持久化能力已具备，不能仅把前端 useState 移植过去就宣布完成。

### 8.4 精选分享的最小闭环

```text
选择要分享的已有结果/报告（可从已保留成果中选择，也可直接选择）
→ 预览成果及其必要口径与限制
→ 服务端按当前用户权限重新校验并生成受控快照
→ 接收方在现有访问策略下读取
→ 后续修改原任务不静默改变已分享版本
```

最小可分享单元是一个能独立理解的成果包，而不是任意摘掉限制的句子。选中结论时，其必要时间、范围、口径、来源和关键限制必须随附；不允许把“尚待验证”的限制删掉后形成确定性结论。改答相近问题后，成果仍保留实际问题与范围，不以原始目标名包装替代结果；后续权限变化也不能追溯性地把旧结果改写为已使用更多资源。

### 8.5 分享与隐私边界

| 对象或情况 | 拟采用规则 |
| --- | --- |
| 默认候选 | 仅提供已产生的业务结果或报告；不展示演示占位成果。 |
| 默认不选 | 原始用户输入、澄清过程、原始附件、代码、内部日志和隐藏资源。 |
| 服务端处理 | 按任务归属、资源权限和分享策略获取真实内容；客户端不能上传整段内容替代权威读取。 |
| 接收方访问 | 复用现有身份与资源访问机制；只读是操作限制，不等于授权。 |
| 无权、过期、空选择或失效 | 返回明确状态；不得回退到整个任务、其他 Block 或默认示例。 |
| 原任务后来变化 | 保持已分享成果引用与上下文一致；更新分享应为明确动作。 |

参考源的白名单过滤可以借鉴，但应过滤业务字段和关联引用，不只过滤 Block.type。下载、导出与分享都是实际获取信息的动作，沿用现有权限规则，不能仅靠按钮隐藏。

### 8.6 进入研发前的条件与最小验收

产品先确认可保留、可分享的成果类型与范围；后端确认既有结果引用、任务关联保存、读取授权及分享生命周期的承接。尚无这些能力时保留已有结果入口，不新建第二套 Artifact 仓库或权限系统。

| 子项 | 独立验收标准 |
| --- | --- |
| 成果保留 | 同一引用不重复；可按任务恢复；移除不删除原结果；新口径不覆盖旧结果；读取继续受授权控制。 |
| 报告预览 | 内容确实存在；定位和边界正确；无权或加载失败不出现替代报告。 |
| 精选分享 | 只包含选定成果及必要上下文；接收方实际读取经过授权；不把只读 UI 当成授权完成。 |

> 本章是后续成果交付设计，不是 Find Data V1 的补修清单。任务内保留不强制依赖报告或分享，分享也不强制用户先保留。

## 09｜C 批次：临时文件与周期任务

### 9.1 C-01 临时文件补充分析

来源实现：仓库处理 CSV/TXT 上传、表头、数据行数和缺少工单标识等错误；后续字段语义主要按列位置赋值，Python 代码与比例结果为 Mock 返回。可吸收用户工作方式，不能迁移为真实语义绑定或计算能力。[S08](#src-s08)

```text
用户在当前任务上传清单
→ 真实解析与必要校验
→ 展示候选字段对应和未解决项
→ 有歧义时确认任务内使用方式
→ 在访问控制下执行补充分析
→ 结果注明临时文件来源与覆盖限制
```

文件绑定仅为本次任务或本次运行的输入关系，不自动发布为 Data Asset，也不回写正式 Business Object 的 Data Binding。遇到无法识别、无关联键、重复键或无法确认范围，应停止对应计算并说明缺口；不按列序号或文件名制造“语义已对齐”。

只有文件解析、数据关联、权限校验与实际执行均有承接服务后，才开放入口。未支持的格式明确提示；生产上传失败不得生成伪 attachmentId 或偷偷替换成示例文件。

### 9.2 C-02 从一次分析到周期任务草稿

来源实现：SchedulePlanBlock 展示频率、范围、指标和步骤，缺参数时不允许确认；确认后收拢为摘要。但 Mock createSchedule 仅返回状态和时间，没有证明真实持久化调度已运行。[S09](#src-s09)

```text
用户提出“以后每周执行这项分析”
→ 从有效分析产物提取任务草稿
→ 确认频率、时区、数据范围与输出
→ 明确触发创建动作
→ 任务中心返回创建结果与任务 ID
→ 对话显示可继续管理的入口
```

必须区分固定历史时间与滚动窗口；只有一次性上传的文件时，不能自动承诺每周获取最新附件。草稿生成不是任务已启用，创建失败不能显示成功。周期运行继续通过现有执行时鉴权，而不是永久复用本次权限快照。

### 9.3 不新增平台分区

文件处理复用既有文件/数据接入能力，周期任务复用任务中心与运行服务。源码中的“企业自动化中心”不作为 Semovix 新菜单。文件、周期任务均为可选分支，不能把每个用户都强行带入“分析—上传—调度—分享”的演示顺序。

| --- | --- |
| 上翻时到达新消息 | 不抢位置；提示单一；点击或手动到底可恢复跟随。 |
| 切换任务或展开详情 | 无旧提示串台，不误触发业务事件或新内容提示。 |
| 澄清成功 / 失败 | 成功转只读摘要；失败保留选择并允许原动作重试。 |
| 历史已确认 / 已失效 | 不能重提；只读查看不修改 Revision。 |
| 建议生成 | 0–3 项、无重复；待确认时不出现跳过决策的建议。 |
| 建议点击前状态改变 | 现有门禁重新判定，不执行已失效动作。 |
| 普通问答 / 明确查看 | 普通问答不切换 GUI；明确查看走 Surface Policy。 |
| 原业务主路径回归 | 候选/方案区分、口径替换、失效计划与权限门禁保持原行为。 |

复用现有类型检查、测试、构建与浏览器 Smoke。在现有组件测试中覆盖三项行为，并在已有浏览器流程补一条“上翻—新消息—返回底部”检查即可；不建设新的多浏览器或全页截图矩阵。

### 11.3 后续独立排期与验收，不回压首批

| 后续项 | 建议先确认什么 | 独立通过标准 |
| --- | --- | --- |
| Data Solution 覆盖与候选说明 | 现有 Coverage/Gap、候选用途依据和资源角色是否充分。 | 资源角色、覆盖与限制不失真；只读查看不触发执行或纳入。 |
| 原目标与可选范围 | 是否能够沿现有合同记录明确接受、本次执行范围与原目标缺口。 | 咨询/拒绝不改状态，接受才推进；覆盖、就绪、完成分开，替代结果不能冒充原目标完成。 |
| B-01 事实分层与多来源依据 | 来源事实、适用判断、验证状态及历史引用能否准确取得。 | 事实与判断分开，来源确实支持对应主张；限制、定位与权限状态真实。 |
| B-01 直接问数与结果追问 | 现有入口和结果引用能否承接明确请求。 | 不强制重复找数；多结果不串台；新运行不复用失效计划。 |
| B-01 分析解释与展示意图 | 当前支持的方法边界与现有工作区能力是什么。 | 不编造因果/预测；明确画图不重复打开，迟到结果不抢占新的用户选择。 |
| B-01 图表/数据视图 | 是否已有同一结果集和适合的显示结构。 | 两种视图一致，切换不查询、不改需求。 |
| B-02 真实运行反馈 | 是否有可信运行标识及阶段事件。 | 真实状态驱动，失败/断线不显示完成。 |
| B-03 任务内成果保留 | 是否可保存、恢复既有成果引用。 | 版本不覆盖、按任务隔离、访问仍受控。 |
| B-03 报告预览/精选分享 | 对应服务和授权边界是否具备。 | 内容完整、范围明确、实际读取经过授权；分别验收。 |
| C-01 / C-02 | 文件、关联、调度服务是否已具备。 | 真实执行与任务中心交接成立后再开放。 |
| 资源详情/交接摘要/原权限表单 | 对应字段是否真实可读，原查看与申请动作是否具备。 | 业务与方案属性不混淆；授权不自动选用；交接、提交和执行状态不混淆。 |

A 完成后，建议先评审“需求覆盖中的范围取舍”和“依据中的事实/判断分层”，并与 V1.1 的紧凑依据查看合并考虑；不得为了采用一个示例同时新增跨域 Scenario、搜索服务或新状态机。候选用途、资源详情与交接摘要随原工作区优化处理；权限表单随原服务需要再处理。图表/数据视图随 Ask 结果工作区排期，成果保留待引用与持久化可用后再做。这是评审顺序，不是新增全量工作包。

> 停止条件：A-01/02/03 的约定行为与原有回归通过，即结束首批。不得以 B/C、范围取舍或依据分层等后续细化未实现判定 A 未完成；不新增 RC 等级，不再对 Find Data V1 开启无限修复。

### 11.4 用场景矩阵验证，不串成新的功能巡演

以下是拟采用行为的独立检查点，只有相关子项进入实施时才验证，不要求用户逐个走完。V1.3 增补的入口、指代、部分执行、分析边界和展示意图用例，不并入 A 批次三项工作包。

| 场景 | LUI 行为 | GUI / 状态要求 |
| --- | --- | --- |
| 用户上翻阅读历史，新消息到达 | 仅提示“有新内容”。 | 保留阅读位置，用户主动恢复跟随。 |
| 用户完成一项澄清 | 展示已确认摘要。 | 历史只读，不因收拢改状态。 |
| 已明确资源、口径与范围，直接要求计算 | 承接现有有效输入，补足真正缺项。 | 不强制重复找数；执行仍经过原门禁。 |
| 从已有结果继续分析 | 确认本次结果引用；仅解释时不重跑原查询。 | 保持该结果的时间和口径，不替换为最新结果。 |
| 两份不同口径结果并存，追问指代不清 | 只澄清基于哪一份。 | 打开历史不自动覆盖当前需求或计划。 |
| “为什么推荐这两项资源？” | 说明分别覆盖什么和现有限制。 | 不自动打开；明确查看时显示当前方案说明。 |
| “打开本次口径依据” | 简短提示当前查看对象。 | 使用原引用版本，不编造文档。 |
| “查看完整结果”后切换图表/数据 | 不重复插入一份回答。 | 同一结果的两种视图，不发起新分析。 |
| “画出最近十二个月趋势图” | 已构成展示请求，沿现有执行规则取得结果。 | 就绪后可呈现；用户期间主动切换/关闭时只提示，不抢回。 |
| 保留当前结果，再切换床位口径 | 保留旧结果，再走既有需求变更链。 | 新旧结果各自携带口径，旧结果不自动成为新输入。 |
| 只发现部分服务使用数据 | 明确当前目标未完整覆盖。 | 不因界面更完整就显示“全部就绪”。 |
| 用户同意只先做床位比较，且必要条件满足 | 完成该次比较后保留服务使用缺口。 | 本次成功与原目标部分覆盖可同时成立；不新增状态中心。 |
| 从偏低比率追问原因或新增床位规模 | 说明已有发现与当前不能证明的内容。 | 缺方法/证据不生成确定原因和行动数值；按需补数，不填演示结论。 |
| 请求报告、分享或周期任务但服务未就绪 | 真实说明当前未提供。 | 不显示已生成、已分享或已启用。 |
| “不使用人口明细还能先看什么？” | 说明有依据的可选范围及不能推导的结论。 | 保留原需求与计划；咨询不当作接受。 |
| 用户明确“先做区域比较” | 说明改为区域比较，不识别实际老年诉求人。 | 走现有需求修改/重评；未完成或失败时不执行新计划。 |
| 用户拒绝改变目标 | 保留原目标，说明未满足条件。 | 不自动选择可查询资源或静默扩大/缩小范围。 |
| “依据在哪，关系已经确认了吗？” | 区分来源事实、适用判断和待验证项。 | 按明确查看动作打开依据；同名字段或对象绑定不作 Join 已验证凭据。 |
| 权限申请已提交或刚获得授权 | 按真实服务状态说明动作权限。 | 不自动纳入资源、不自动执行或补出结果。 |
| 新范围结果被保留、报告或分享 | 使用实际执行的问题、时间与口径。 | 原限制随成果保留，不能改称原目标已完整完成。 |

### 11.6 体验验收与真实业务验收分开｜V1.3 修正

| 验收对象 | 依据 | 通过能说明什么 | 不能说明什么 |
| --- | --- | --- | --- |
| A 批次体验优化 | 11.2 的三项行为、原有回归与现有 Smoke。 | 当前约定的阅读、决策与建议展示已经完成。 | 真实资源发现、查询计算和分析解释已全部生产可用。 |
| 后续某项能力 | 该项已批准范围、实际数据与服务条件、对应独立验收。 | 该项在约定范围内成立。 | B/C 全部能力都已经成立。 |
| 真实业务主链路 | 明确场景下的实际资源、真实运行结果、数值对照、权限与解释边界。 | 该场景在此次环境和已确认边界内跑通。 | 所有行业、资源和任意问题均可可靠处理。 |

**A 验收通过即结束，不等待生产联调；生产能力则不能用 UI 或 Mock 通过替代验收。**后续开始真实集成时，选择一个明确业务场景，在原有测试中补少量能暴露错误的检查即可，不建设大型评测平台，不用百分比目标代替具体正确性。

| 最小业务检查 | 验证重点 |
| --- | --- |
| 已明确资源与口径的问数 | 能直接准备有效计算，不强制重新找数；输入与授权均经过实际校验。 |
| 两份不同口径结果的追问 | 解释绑定正确结果；有歧义只澄清对象，不改写另一份结果。 |
| 原目标部分覆盖 | 经用户同意可完成具备条件的子问题，保留原缺口；必要输入缺失时不能执行。 |
| 咨询替代方案但未接受 | 原目标、已选资源与计划不被自动替换。 |
| 计算值与业务口径对照 | 将实际查询结果与按已确认口径独立核对的结果比较；需要区分整体比率、加权比较与分组比率平均值，不能混用。具体公式以本次正式口径为准。 |
| 查询成功但原因证据不足 | 允许描述与解释结果，不能仅凭数值或一条定义引用编造原因、预测和行动规模。 |

这些用例按相关能力进入实施时取用，不要求新增第二套完整 Fixture 或全量浏览器矩阵。对照结果存在差异时记录口径、范围、证据和原因；未确认前不把业务结论标为通过。真实服务和测试结果未在本轮材料中提供，因此本版不报告生产验收结论。

本轮五项修正均以既有规则消歧为目的：不做通用路由器、不做上下文中心、不做三套状态机、不做通用因果引擎，也不把 GUI 意图判断变成必须补齐所有自然语言表达的工程。
